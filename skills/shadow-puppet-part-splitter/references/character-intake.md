# 从单张图到可编辑组件：执行入口

## 能力边界与职责

旧工具的 `extract` 接收现成 mask，不会辨认肩、袖或手。新入口把**经观察的语义标注**编译成独立 PNG 和统一坐标的 manifest；不是一键 AI 分割。执行者负责看图并给出初版边界、关节和遮挡，不能把整套坐标填写工作默认转交用户。复杂边界可调用实际可用的分割工具生成候选，再用同一流程复核。没有配置的模型不可写成已可调用依赖。

平面 RGB 图只记录最终合成结果：看不见的肢体、被手挡住的衣纹、半透明皮革下面的原背景都不能唯一反推。分开处理三个问题：可见像素分配、隐藏区补绘、关节/遮挡装配。不要让生成器重画整套组件来解决坐标问题。

## 1. 选择源图和结构

优先使用完整、无裁断、清晰、少透视、肢体有间隙的单角色设计图，保留源文件与像素尺寸。背景透明仍需检查孔洞；白色不自动视为透明。视频帧只能作为带背景、灯光和压缩的测试样本，不等于原始设计图。

按目标动作定义节点和可见绘制片：肩到肘、肘到手是否需要独立旋转，宽袖是否应当一体摆动，鞋后是否存在可见小腿，长裙是否需要独立裙片。为一张图强行补出标准人体骨架会制造不存在的结构。

先标一条最具风险的关节链。对遮挡区写明：谁离开后会露出谁；例如手从腰间抬走时，必须补的是躯干被遮住的衣料，同时检查手腕根部。只给手加一个关节圆片无法补上腰间空洞。

## 2. 创建可修订标注

用 [本地标注编辑器](../assets/annotation-editor.html) 打开源图，或由执行者直接写 JSON。编辑器支持画/拖动多边形、孔洞、关节、父级和 z；载入/保存 JSON。不会上传图片；浏览器执行受环境策略约束，不能绕过禁止的文件访问。

标注文件格式 `character-annotation-1`：

```json
{
  "schema_version": "character-annotation-1",
  "source": "source.png",
  "source_size": [800, 1000],
  "hidden_policy": "concept-covered",
  "ownership": "ordered-last-wins",
  "subject": {"mask": "subject-mask.png"},
  "nodes": [
    {"id": "body", "parent": null, "pivot_global": [400, 520]},
    {"id": "arm", "parent": "body", "pivot_global": [440, 290]}
  ],
  "parts": [
    {"id": "body", "node": "body", "z_index": 1,
     "visible": {"mask": "body-visible.png"}},
    {"id": "arm", "node": "arm", "z_index": 2,
     "visible": {"polygons": [[[430,280],[520,300],[540,570],[430,550]]]}}
  ]
}
```

以上坐标仅说明格式，不是真实角色标注。`subject` 是独立审查的角色范围，不能简单取所有部件并集来掩盖漏分。每个 region 用全画布二值 L mask 或多边形数组二选一，可附 `holes` 多边形数组。软边来自源 alpha，所有权遮罩不做羽化，避免两层软边叠暗。

`exclusive` 遇重叠拒绝；`ordered-last-wins` 按 parts 数组后项取得可见像素，报告交叠面积并输出交叠图。此优先级与 `z_index` 不同，前者分配原图所有权，后者定义回组绘制顺序。可以将躯干作为宽选区后由肢体优先扣除，但必须检查躯干剩余片：不可藏有袖边、手或背景。每个角色像素必须且只能有一个可见所有者。

编辑器记录源图 SHA256。加载同尺寸新图或未绑定的旧标注时阻止导出；执行者核对边界后点击“核对完成，确认源图”才能重新绑定。编译器对已记录哈希的输入强制验证，避免尺寸相同的修订稿误用旧标注。旧标注仍可编译，但报告为 `legacy-unbound`，不能据此声称验证了源图身份。

全部坐标沿用源图，不能对各组件分别缩放再凭眼对齐。节点锚点是实际关节候选，不是裁剪中心。左右、近远侧命名由观察确定，不盲套左右肢体。

## 3. 编译和回组

从本 skill 目录执行：

```bash
python scripts/compile_character.py /project/character.annotation.json --output /project/character-v1
python scripts/puppet.py check /project/character-v1/manifest.json
```

编译器输出独立 `parts/*.png`、全画布可见 mask、裁后推测 mask、`manifest.json`、来源哈希和 `compile-report.json`，以及 `preview/` 中的回组、源主体、差分、所有权和交叠图。拒绝覆盖已有输出，迭代改用新版本目录。

无分配像素、空件、非法节点或环会报错。零姿态差分比较 alpha 和预乘 RGB；变动非零时状态为 `blocked`、进程退出 2，保留失败证据。新编译 manifest 声明其编译报告；普通加载、预览及 Blender 导入拒绝 blocked、缺少报告或产物哈希不匹配的版本。报告记录源图、标注及所有引用遮罩/补图的输入哈希和输出文件哈希。编辑产物后必须重新编译，不手改报告“放行”。旧的无编译标记 manifest 维持兼容，不获得新的编译验证事实。诊断失败版使用专用诊断工具；编译内部和明确诊断调用可绕过生产加载限制。

`pass` 只表示源保留区回组一致，不表示分件语义、背景分离、隐藏修补或动作已经正确。

逐件看 PNG，再对照原图：头完整吗、袖边还粘在腰身吗、手腕是否带走不该动的纹样、内部背景孔洞是否遗漏。保留零差分不阻止错误的语义切割。

## 4. 显式隐藏修补与试动

仅在 `inferred-repair` 下给部件添加：

```json
{"repair": {
  "file": "body-hidden-rgba.png",
  "region": {"mask": "body-hidden-mask.png"},
  "reason": "手离腰后暴露的衣料；依据邻接纹样推测"
}}
```

补图与 mask 均采用完整源画布；补图必须 RGBA。编译器强制排除该片原可见区域，再合成补图，因此不会改写该片原像素。补图由受控编辑或可用图像编辑工具制作，编译器不自动生成。修补在原姿态应藏在遮挡片后；半透明遮挡仍可能改变原姿态，差分会阻断，需重新设计而不是调高容差放过。

使用 [已有 IO 和预览工具](tools.md) 导入同一 manifest，保持相同父级和锚点，试参考姿态、目标极值、中间角度与组合。把每个像素片的可见归属和隐藏搭接分开，不可重复复制整片手臂充当遮挡修复。

先记录目标范围，后记录实际检查结果：仅修正边界失败的部件、错误锚点或特定隐藏区，重编译、回组、复测相同动作。保留失败版；不能通过降低目标范围静默宣布通过。更改 z 顺序后重测全部隐藏片：原来藏在上层下的补片可能变成前景，必须同步调整或移除，不能只看新修好的关节。若刚性袖片无法覆盖整条接缝，改变拆片/背片结构或明确选择另一种变形方式。

## 5. 验收门槛与上游反馈

- 概念图阶段：完整性、朝向、肢段辨识通过；隐藏区不可验证应标记。
- 资产阶段：每件可独立读取，原姿态差分通过，边界/孔洞/层次目视通过。
- 绑定阶段：原坐标导入、父子跟随、关节方向和实际限位经过工具验证。
- 动作阶段：目标范围内连续试动并审阅，不用四张静帧代替；记录失败角度、接缝区域和接触误差。
- 镜头阶段：本镜头动作及画幅、背景下通过，才允许进入成片制作。一个角色通过不证明所有角色都能自动处理。

反馈到概念生成：提供低遮挡的装配基准姿态；需大幅摆动的衣片另给隐藏结构依据。反馈到动画导演：提供实际检查的角度/动作、尚未通过的目标及替代结构，导演先处理，无法处理的进入待审问题文档。

具体的像素、转轴、扫转连接与转轴拟合工具见 [装配诊断与优化](assembly-diagnostics.md)。
