# 参考图到可用素材和连续表演

先让一个具体行为在目标画面中成立，再扩展角色能力。一次制作任务持续负责素材、动作、连续预览和局部返修，不能交出 PNG 或骨架后把尚未成立的动作留给下一环。

## 输入与边界

先实际查看参考图，并读用户动作要求、镜头尺度、时长和已有工程。缺少镜头信息时采用便于观察行为的固定侧面全景，简记假设即可；没有参考图不能编造边界、坐标或已完成资产。

保留角色身份、可见轮廓、花纹和镂空。制作项目沿用其明确选择的隐藏区策略；未限定的独立任务使用 `inferred-repair`，允许为当前动作补必要搭接并保留实际 mask。`concept-covered` 是主动选择的严格路线，缺少依据就报告具体缺口。动画预览可使用候选素材，不等待逐件审批；正式资产和影片 Gate 仍由项目既有约定管理。

工具入口是 [scripts/toolbox.py](scripts/toolbox.py)，用法见 [tools](references/tools.md)。已有遮罩、锚点和轨迹直接复用；没有时由执行者依据参考制作并检查，不能把它们重新列成用户必须交来的输入。工具不自动语义分割、补画或设计动作；需要时使用实际可用的图像编辑能力和项目持久脚本，无法完成则说明具体缺口。

## 1. 先选行为和表达方法

在已有动作记录或 `motion_plan.json` 中简记：观众应读到什么、关键变化、实际画面尺度与朝向、接触对象、身份不变量。选一个能暴露难点的代表行为先做；用户要求的其他动作保留为待做，不因试制而删去。无需新建简报、组件树审批或单独方案文档。

| 需要表达的变化 | 优先试用 | 扩展条件 |
|---|---|---|
| 远景移动、掠过、静态群众 | 完整角色图与整体轨迹 | 轮廓变化确实可见时再分件 |
| 转头、摆臂、简单振翅 | 少量刚性分件 | 简单分件无法保持所需轮廓或接触时 |
| 张喙、握持、大幅轮廓变化 | 同锚点姿态／局部替换 | 需要连续中间形态时 |
| 宽袖弯曲、近景连续表演 | 局部形变、专用姿态或更完整绑定 | 先用实际镜头证明需要，另验纹样畸变 |

方法可组合，不默认完整人体、每翼多段、骨架与服装分层或 Blender。不同镜头可使用同角色的不同结构，但身份、朝向和衔接须一致。当前通用渲染器只支持层级平移、旋转和缩放；姿态替换、动态层序、局部网格形变需目标运行时或项目脚本实际实现，不能往 JSON 写一个字段就声称支持。

## 2. 制作当前行为所需的最少真实素材

- 可见部分优先确定性提取，精确控制内部接缝，保留外轮廓、细线和 alpha 孔洞。白背景、白纹样与镂空不能全局按白色删除。
- 先制作会动或会暴露的部件；其余可保留整片。独立查看每件，纠正误带的袖边、裙摆、重复肢段与近远侧混淆。
- 为实际使用的每件确定跟随对象、转动位置、前后层序和被遮住的根部。已有可靠 alpha 时可宽覆盖外部透明区，再与源 alpha 相交；不能跨入其他部位。
- 需要补全时按 [repair](references/repair.md) 分离可见保护区和推测区，使用最少连接材料。脸、纹样和可见设计继续取源图，不整图重生成。
- 在 `manifest.json` 保存原坐标、裁剪位置、节点和绘制顺序；数据见 [manifest](references/manifest.md)。无需重复建立 `parts_plan.json` 或每层标注板；只有边界难以判断时制作局部诊断图。

一张拆件拼版不能替代独立 PNG。没有相对运动的细节不要为了目录完整而拆开。

## 3. 装配并设计完整动作

尽早把真实素材放入目标画幅、实际比例和背景，先检查静止回组，再设计连续动作。无目标后端时可先用 Pillow 二维预览；需要可编辑 Blender 工程再读 [Blender 工作流](references/blender-workflow.md)。平台不存在时不无限等待，也不把二维预览说成已通过引擎导入。

动作先安排有意义的关键状态和时间，再求各节点轨迹：准备／观察 → 发力／接近 → 接触或主要变化 → 跟随／停稳，按具体行为取舍，不给每个动作机械加入所有阶段。

- **整体运动**先决定路径、速度变化、起停和落点；局部摆动跟随整体节奏，不用全身同相位正弦代替表演。
- **接触**明确何时接上、由谁带动、何时释放。手持／衔取的物品在接触段跟随接触点；脚在支撑段保持接地。若工具不支持换父级，可烘焙明确世界轨迹或在运行时实现，实际连续检查交接帧。
- **重心与支撑**按镜头可见程度处理。走路同时处理根位移和支撑脚，坐下有骨盆下降、承托与停稳；不能只转几根骨头就认定完成。
- **次级运动**在主动作可读后添加头部跟随、袖摆、尾部延迟和小幅回弹。没有行为作用的位移、左右翻面和持续抖动应移除。

`motion_plan.json` 的 `clips[].frames` 保存明确帧号和节点变换，兼容现有 Blender IO。每个关键帧是完整姿态：未写的通道回默认值，不能误以为沿用上一帧。插值默认线性；缓入缓出、停顿和快慢变化由执行者写入足够的采样键，不能只改动作名称。目标／已验收范围在需要关节限位时分别保留，不默认要求所有关节 ±30°。

## 4. 每轮直接生成并观看连续预览

```bash
python scripts/toolbox.py animate --manifest /path/to/manifest.json --motion-plan /path/to/motion_plan.json --output /path/to/preview/v1
```

默认逐帧插值并输出 GIF、联系表和同目录 `preview.json`；无需 Blender 或 FFmpeg。`--stage` 可加入同画幅场景底图；选一个片段用 `--clip-id`。MP4、完整配置和预算见 [tools](references/tools.md)。每轮用新的预览目录，保留前一版对照；同一素材和动作输入继续复用。

先以目标速度完整观看，再查看接触帧、动作极值、中间帧与循环接缝。至少检查：

- 不读动作标签也能辨认行为，节奏有准备、主要变化和结果；
- 目标画面尺度下轮廓清楚，运动连续，起止状态成立；
- 接触物体没有提前漂走，支撑和重心可信；
- 根部不露缝、补片不穿帮、纹样不拉坏、遮挡顺序正确；
- 循环不跳，相机画幅不裁掉必要动作。

联系表、帧差、单骨权重和关节交叠只能定位问题，不能代替连续播放。无法播放时按时间顺序检查全部帧并标明未完整播放，不把编码成功写成观感通过。

## 5. 定位一个问题，修后重跑同一片段

| 看到的问题 | 优先修改 |
|---|---|
| 露缝、重复边、补片外露 | mask、归属、搭接轮廓与层序 |
| 连接正确但动作僵硬／不明所以 | 主动作轨迹、节拍、接触和停顿 |
| 脚滑、抓取脱手、衔物漂走 | 支撑段、根位移和接触点轨迹 |
| 扭曲、大片衣服翻穿 | 表达方法：减少无用分件，改局部替换／形变或专用姿态 |
| 身份、核心轮廓、纹样变化 | 回到对应视觉设计局部返修 |

每轮只修与失败有关的素材或动作，重新生成相同时间范围并对比前后。不要以减少目标动作、缩小角度或更换镜头遮住失败；确需改变用户要求时明确报告差异。重复失败应更换表达方法并说明原因，不能堆更多组件或无效生成。

## 交付与扩展

先交付实际使用的素材、`manifest.json`、`motion_plan.json`／项目动作脚本和连续预览；有工程需求再交付可编辑场景。结论和残留问题直接写在已有任务记录或预览说明，不强制另建 QA 报告、组件树、拆件板与多套审批文档。

只在代表行为成立后扩展其他动作和镜头，把重复成功的部分固化为工具／模板。正式资产另做范围内的透明边缘、坐标、层序与依赖检查；Blender 刚性路线再验证单骨权重、角度符号、限位和重开。技术通过、观看结论和用户确认分别记录，不能互相替代。

## 测试入口

`python -m unittest discover -s tests -v` 检查确定性工具与连续预览。真实角色行为用例见 [evals/evals.json](evals/evals.json)；机械样例不证明皮影美术或动作质量。
