# 技能协作与交付契约

在制作项目选用工具、交接素材或定位职责冲突时读取本页。阶段、批准与 Gate 以[总控](工作流-全流程总控.md)为准；本页定义能力调用和交付接口，不是自动调度器，也不证明某个后端已经实现。

## 职责与写入边界

| 层／角色 | 负责 | 写入与交付 |
|---|---|---|
| `ancient-tales-production` | 专业流程、阶段关系、交接与验收依据 | 当前项目的剧本、导演母版、视觉契约和专业审阅记录 |
| 制片／总控角色 | 调度、上游绑定、阶段推进和阻塞处理 | 聚合专业结论至唯一 `生产总控.md`；批准依据须来自真实确认 |
| 导演角色 | 镜头叙事、表演、节奏与持续复审 | 导演母版及带范围的导演审阅结果；总控中的 `director_*` 字段仅表达专业结论，不自行批准资产或越过 Gate |
| 通用能力 Skill | 在明确输入和限制内制作、处理与验证产物 | 工具原生 manifest、技术证据、实际产物和限制；不修改影片阶段或批准事实 |
| `ancient-tales-pipeline` | 技能锁与安装、资产索引与传输、文件完整性检查 | `skills.lock.json`、安装回执、`assets.pending.json`／`assets.lock.json`；不判断叙事、视觉质量或批准有效性 |
| 项目后端 | 原生资源适配、场景装配、时间线和渲染；承担明确分配的 rig／三维制作项 | 原生场景、时间映射、镜头输出和后端检查证据 |

这些是职责，不要求启动多个 Agent。同一 Agent 兼任时，仍区分专业审阅、阶段推进和用户批准。导演可提交 `changes-requested`，由总控记录阻塞；技术 `ok`、上传成功或哈希通过均不自动产生 `approved`／`locked`。

## 调用关系

```text
production：读取项目配置、锁定上游，形成导演意图与素材契约
  → 按下表选择能力 Skill／外部工具，明确输入、输出和策略
  → 素材制作与专业验收，记录实际确认及资源版本
  → 项目 backend：适配、装配、时间线、真实镜头输出
  → 导演复审 → 总控核对 Gate 条件与批准依据

pipeline：在需要时提供技能安装、资产上传／恢复／字节校验
```

`visual_profile` 选择视觉与资产单位，`implementation_profile` 绑定后端，两者独立。profile ID 与 `blender-styles` 的风格 ID 不必同名，项目配置须显式映射。后端入口从项目配置及其 `docs/backend/` 解析并核对真实脚本；素材 Skill 不能作为后端。技能安装仍只自动补齐 `requires`，下表能力按选中路线显式安装。

### 能力选择与返回值

| 需求 | 选择入口 | 输入 → 交付与限制 |
|---|---|---|
| 来源与既有知识查询 | [query-obsidian](../../query-obsidian/SKILL.md) | 问题与查询范围 → 来源链接、证据及缺口；制作状态留在项目，知识蒸馏另行使用 distill-to-obsidian |
| 皮影概念参考 | [shadow-puppet-image](../../shadow-puppet-image/SKILL.md) | 视觉定义、姿态、连接与可动性约束 → 静态角色图及检查；不代表独立件或动画可用 |
| 平面组件制作／确定性处理 | [shadow-puppet-part-splitter](../../shadow-puppet-part-splitter/SKILL.md) | 源图、动作需求、遮罩与隐藏区策略 → 独立 PNG、原坐标、组件 manifest、验证与推测说明；需要动画才走绑定试动 |
| 完整纸偶姿态／静态景层处理 | 拆件 Skill 的 [tools](../../shadow-puppet-part-splitter/references/tools.md) 子入口 | 已有图像、遮罩、层序 → 透明提取或静态回组；不自动进入关节拆件／骨架流程 |
| 有动作库匹配的逐帧姿态约束 | [continuous-action](../../continuous-action/SKILL.md) | 当前 catalog 中动作、视角、角色身份及事件要求 → Blender 参考帧、生成帧、对应 manifest 与连续性 QA；无匹配动作按该技能处理，不默换动作源 |
| 自由精灵动作或生成帧后处理 | 外部 `sprite-gen` | 视觉身份、动作与时间契约 → 透明序列／图集、原始 manifest、锚点、逐帧时长和预览；见[精灵流程](工作流-场景精灵动画.md)，不承诺逐帧精确匹配 Blender 姿态 |
| 三维造型、rig、相机与渲染 | [blender-python-modeling](../../blender-python-modeling/SKILL.md) | 参考、目标完成阶段、动作与镜头限制 → 持久脚本、场景／模型、模块审阅和渲染证据；影片时间线仍由项目后端集成 |
| 黏土等 Blender 风格 | [blender-styles](../../blender-styles/SKILL.md) + 通用建模 | 已选风格及项目映射 → 配方、材质／灯光／节奏设置与风格证据；不取代角色身份与建模验收 |
| 缺少背面／侧面设计 | [concept-multiview-sheet](../../concept-multiview-sheet/SKILL.md) | 已确认单视图及设计约束 → 推演多视图与技术线稿；需审阅后才能成为上游，不作为实测几何 |

精灵生成、库动作参考与后端 rig 是不同方法。素材契约须说明已烘焙的局部运动与后端位移／相机运动，避免重复叠加。三维绕拍、体积受光或可编辑接触不能仅因生成工具可用就降为平面精灵。

### 调用前核对

1. 明确当前项目、视觉与后端绑定、上游版本，以及本轮是探索还是正式制作。
2. 只读取选中能力的 SKILL 与相关资料，核对实际版本、可执行入口、动作目录和支持的输出。外部工具不由安装器自动安装；缺失项记录为缺口。
3. 约定输出目录、资产单位、隐藏区策略及时间坐标；输入未经锁定时只能产生候选。
4. 调用后保留原生结果，映射成下述交付记录。技术、专业视觉审阅和用户批准分别记录。

当前能力表是规范映射，不是经过全部后端验证的兼容矩阵。具体实现支持状态与证据保存在项目配置中。

## 交付契约

以下字段可以放在既有项目 manifest 或引用记录中，不要求再复制一份总控。字段可引用解析；不能用一个文件名或目录代替具体版本。工具原生 manifest 保留，适配层引用它，不强行把工具 `ok/cached` 改写为生产状态。

| 交接 | 必须携带的信息 |
|---|---|
| 导演 → 美术／素材 | 锁定剧本、分镜、故事板与 Animatic 引用；`shot_id`、fps、镜头帧范围、元素／资产 ID、动作事件、起止状态、接触／遮挡及验收范围 |
| 素材规划 → 能力 Skill | 项目与 profile 绑定、选用方法及理由、视觉定义版本、输入引用、输出规格／路径、`hidden_region_policy`、动作时间和运动分工 |
| 能力 Skill → 素材验收 | 原生 manifest、逐文件哈希、生成／处理参数、原坐标或锚点、动作映射、实际完成范围、技术证据、推测区和未通过项 |
| 已验收素材 → 后端 | `repository_id/project_id/asset_id/version/path/uri/sha256/size`、批准回执引用与被审哈希、对应 `shot_id`、原生 manifest 及导入映射；不按镜复制共享二进制 |
| 后端 → 导演／总控 | 后端版本与实际输出引用、镜号及时间映射、连续播放证据、与母版的偏差、`review_scope` 和覆盖镜号 |

时间数据须声明是镜头本地帧、全片帧还是源动作帧，以及起点、终点是否包含、fps 和逐帧时长。后端转换须保留映射。版本用于身份，SHA-256 用于字节完整性；历史版本不因重新扫描而重命名。

### 隐藏区策略

- `concept-covered`：本制作工作流的组件路线采用此策略。必须有已审概念／状态图依据；缺失时退回视觉定义，不启用推测补全。
- `inferred-repair`：通用拆件独立任务可按其规则补全运动暴露区，交付推测遮罩、依据与活动证据。用于制作项目须先形成明确的新契约并审阅，不能静默替换严格路线。

策略不满足时返回缺口。既不以更低的目标活动范围冒充完成，也不为遵守上层流程而省略下层必须的技术验收。

### 审阅与状态

Gate 4 使用 `review_scope: sample`，记录覆盖的 3–5 个正式镜号及独立样片时间轴。全片复审使用 `review_scope: full-film`，覆盖全部正式镜号；样片证据可以引用，但不能代替未审范围。

阶段产物状态遵循总控；素材需求计划状态、工具执行状态与生产批准分开表达。pipeline 的 `assets verify` 只证明本地文件大小和哈希匹配，不证明项目身份字段、批准回执、视觉质量或 Gate 条件有效。这些须在专业交接中核对；当前工具没有自动生产契约验证器。

## 两条交接示例

- **皮影组件动作**：导演锁定接触与遮挡 → 素材契约选择 `concept-covered` → 概念缺少肘后衣片时先补图审阅 → 拆件工具提取、回组，按动画需求试动 → 记录 PNG／组件 manifest 与批准引用 → 项目 Godot／Blender 适配并输出代表镜头 → Gate 4 样片审阅。拆件试动成功不等于 Gate 4。
- **黏土三维镜头**：导演明确绕拍与接触 → 项目选择 Blender 后端并映射黏土风格 → `blender-python-modeling` + `blender-styles` 制作可编辑模型／rig 和局部动作证据 → 后端装配相机、时间线及音画 → 输出样片复审。默认不转精灵，不把建模模块验收写成影片批准。

以上示例说明接口与责任，未声称已在外部后端实际执行。
