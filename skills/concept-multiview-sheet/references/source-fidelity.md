# 忠实于原图，与多视图一致性分开验收

从照片/现有设计制作可用 3D 模型时，默认目标是 faithful reconstruction：保持可观察的设计身份，只补投影和缺失视角。设计探索只有在用户明确要求重新设计、风格变体或备选方案时采用。不要用“造型语言相近”替代原物。

## 生成前固定原图约束

保留原图及哈希，记录原图视角/透视、遮挡、归一化方向和 observed/inferred/unknown。逐项列出可观察的轮廓、部件数量、开口、连接、相对位置、材质边界及需要保留的文字/标记，并标识关键项。例如五组双辐条不是“五辐”或“十根细杆”；带独立勺子的杯子不能只剩杯子。

提示词必须提供实际原图，而非仅提供 Agent 的文字总结。可观察的身份标记不能因模板里的“no branding”被统一删除；应禁止发明新标记，原图模糊文字保持未知，不补出清晰的猜测。

如果输入本身不是正视图，可先生成规范正视图 A 并与原图核对；A 通过可观察身份检查后再扩展视图。用户只需要某个规范视图时，可交付该视图并注明不能约束的深度；完整建模交接仍按用途补齐必要视图。原图已经是合适可信视图时直接复用，避免无意义再生成。

## 第一关：原图 → 生成图

比较的是观察到的同一设计，不是生成图之间是否互相像：

- 数量与身份：部件、孔洞、辐条、紧固件、附件和可读标记。
- 主次轮廓：杯身收口、把手曲线、勺碗、铸造辐条截面/宽度和负空间。
- 连接与配置：勺子摆放、把手连接点、阀门相位、关节/机械状态。
- 材质与颜色：允许中性光照取代环境反光，不允许换成另一种材质/颜色块或擅自抹去身份细节。

透视原图与正交图不能直接做像素 IoU 或把像素宽高比当实测尺寸。必要时增加同原图视角的见证图辅助比较，并记录匹配角度和剩余不确定；它本身也不能证明一组图存在唯一真实 3D 解。

使用 [源图审查模板](../assets/source-fidelity-review-template.json)。逐项记录原图区域、候选区域、具体 finding、状态和证据哈希。关键特征失败/未知就不得通过；不把所有预期特征批量复制为 passed。隐藏背面/厚度不能放入 observed 清单后声称“已还原”。

## 第二关：生成图之间

独立按 [预建模审查](pre-model-review.md) 和 [一致性检查](consistency-review.md) 核对投影、共同尺度、遮挡和固定配置。源图正面很像，但侧视图的勺碗随相机旋转，或侧面/顶部轮胎厚度互相矛盾，仍不具备建模就绪条件。反过来，一套完全一致但改变辐条/杯把的图也不忠实。

可以用归一化尺寸闭合关系提供证据：轮子正面 X/Z、侧面 Y/Z 与顶部 Y/X 应能解释同一实体。先确认完整轮廓、轴向和分割，再看残差；边界盒不是语义测量，更不是物理尺寸。容差依分辨率、设计和用途声明，不能到处套固定像素阈值。只允许有记录的整体等比尺度校正，不拉伸/扭曲某一方向来隐藏矛盾。

两关分别记录。源图忠实度和跨视图审查都合格，才交接对应的 controlling 区域；局部失败只允许明示且不受影响的范围，无法界定时保留 preview-only。未通过渲染图不生成线稿、不进入受影响区域的精细建模。

## 可追溯交接

保留 generation-record.json：实际工具、引用原图及哈希、提示词及哈希、输出及哈希、时间和重要推断。生成工具成功不证明图像正确。Blender 消费端用 reference_preparation.py 验证路线/记录新鲜度，再独立验证 multiview-review 与导入标定；检查器不替人看图，也不能自动证明原图忠实度。
