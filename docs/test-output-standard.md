# 测试输出文档规范 v1

本规范适用于 Skill 的创建、修复、优化与回归测试。每轮输出必须先回答：输入是否有效、产物实际怎样、相对指定基准哪些改进/无变化/变坏/无法判断，以及本次证据能支持什么结论。测试报告不是某个模型的修补清单，也不能由总分或“文件已交付”替代。

与 [评测规则](evaluation-policy.md) 一起执行。使用 [报告模板](../evals/templates/test-output.md)。底层运行记录继续使用 [现有 schema](../evals/schemas/task-run.schema.json)，本规范补充面向用户的报告，不另建一套运行协议或 Skill。

## 1. 每轮的边界与闭环

1. **声明本轮问题。** 指定比较哪两个 Skill/流程版本、预期改变什么、保护什么；指定基准 run/task/repeat，不能看到结果后挑最弱的一轮作为唯一对照。与首轮基准、最近一轮的比较分开列出。
2. **冻结输入与条件。** 在执行前固定用户任务、原始参考/资产、起点、版本、预算、评分器、指标方向、容差及通过条件。未提交的 Skill 必须记录工作区补丁/内容哈希，不能仅写 HEAD。
3. **执行并检验输出。** 保留实际收到的输入、工具调用、所有候选、失败、重试和最终产物。先检查输出能否接受测量，再检查用途/质量是否通过；二者不能混为一谈。
4. **冻结评测报告。** 同一评分器检验基准与候选，输出逐项变化和证据。此时不修模型、不改阈值、不补造先前门禁回执；后续补充发现写更正/复评记录并保留旧报告。
5. **由报告形成改进假设。** 若继续优化，另立修改记录，说明作用于哪个可复用 Skill/流程、预计影响哪些指标、用什么新测试验证。已获授权的优化可以继续，但测试、修改、再测试必须有独立记录。
6. **重新从约定起点测试。** Skill 能力测试通常重新消费相同原始输入；不能把手工修好的测试模型喂给新版后声称 Skill 提升。若测的是局部修复能力，损坏资产就是固定输入，旧/新流程都从同一快照开始。

正式版本效果比较需要相同预算和成对重复；开发中有意改变预算、工具或路线的探索仍可报告产物差异，但必须标为探索，不能声称受控 Skill 收益。

## 2. 输入检验：声明的输入与实际输入都要核对

报告必须包含以下项目的基准值、本轮值、核验状态及证据：

| 项目 | 至少核验的内容 |
| --- | --- |
| 用户任务与用途 | 原始要求、交付格式、质量标准、对象范围是否一致；中途新指令/豁免逐条记录 |
| 原始输入 | 每个参考图/资产的路径、哈希、可读性、必要内容；基准输入是否被改写 |
| 起点与上下文 | 新建/修复、已有资产、可见知识/历史案例、人工给定参数；是否向一组泄露已有答案 |
| Skill 与工具 | 实际 Skill 内容/依赖、脚本与评分器哈希、实际运行模型标识、Blender/插件/导出器版本；未知值明确写未知 |
| 预算 | 候选数、质量修正次数、生成次数、时间/token、人工介入，以及面数等交付资源约束 |
| 中间产物 → 下一阶段输入 | 实际引用哪张生成图/哪版模型，是否经过适配的忠实度/结构检查，传递的文件与哈希是否一致 |

同一张原照片不代表输入条件完全相同：额外生成参考、不同姿态、人工标注、历史配方、不同初始模型均需记录。中间参考图的“生成成功”“忠实原图”“多视图一致”分别检验。明确允许用有缺陷参考做探索的豁免须保留，不把它改写为参考已通过。

逐项可比性为：**一致 / 有意变化 / 不一致 / 未知**。说明影响：哪些指标仍可作描述性比较，哪些不能归因于 Skill。不能因有一项不一致就藏掉其他可测差异，也不能只写一句“不可比”后结束。

## 3. 输出检验：通过执行不等于通过用途

每个 task/repeat 分别保留首候选、预算内修正后候选及最终阶段，禁止只展示挑选后的最好结果。

- **产物身份与完整性：** 实际文件、哈希、文件范围、可读/重开、是否混入无关对象、是否使用了旧产物。缺失产物记失败，不能记跳过以缩小分母。
- **结构与数据：** 在实际求值/导出表示上检查内容。Blender 多边形无退化不等于三角化后无退化，源文件正常不等于 GLB 重载正常；把检查层次与阈值写清楚。
- **行为与用途：** 实际运动、连接、变形或消费过程，不能只用组件数量、API 成功、文件大小或静止轴心代替行为。
- **外观与参考一致性：** 具体区域、相机/姿态/光照条件、原始参考和产物的对照、审阅者及差异。保留未匹配的区域，不把隐藏推测计为已还原。
- **流程与成本：** 检索/分支选择、前置检查是否执行、全部重试、生成调用和人工介入；区分建模成本、一次性环境安装成本与本次复评成本。

检查状态统一写 **通过 / 失败 / 未知 / 未运行**；不适用必须说明适用性依据。测试本身是否有效、产物是否达标分别给结论。合法的测试完全可能得到失败产物；测量覆盖不足则标记证据缺口，不能默认通过。

## 4. 用户报告必须采用的顺序

### A. 测试结论摘要

先给“哪些变好了、哪些没变化、哪些变坏了、哪些不能判断”。说明比较对象、样本/重复数、完整通过数及分母。未重测的角色/案例单独列出，不能写成“无变化”。

### B. 输入与可比性检查

逐项列出第 2 节的实际检查结果，链接输入清单与哈希、运行记录。改变项说明原因及归因限制。事后复评必须标识为事后，不伪装为运行前冻结的实验。

### C. 输出检验结果

逐例列出结构、行为、外观、导出及流程检查的状态、实测值和证据。格式检查、几何检查、用途检查不能合成一个“验证通过”。

### D. 逐项变化表（报告的主体）

至少包含：

| 对象/范围 | 指标与方向/容差 | 基准输出 | 本轮输出 | 绝对变化/相对变化 | 分类 | 证据与判断依据 |
| --- | --- | --- | --- | --- | --- | --- |
| 实际区域或能力 | 单位、越高/低越好、预设容差 | 实测/状态 | 实测/状态 | 可计算时给出 | 四类之一 | 基准和本轮的具体记录 |

分类规则：

- **改进：** 同一检查在可比较范围内出现有证据支持的改善，并说明是质量、行为、成本还是流程的改善。
- **无变化：** 同一范围有实际观测，变化处于预设容差/评审档位内。必须注明粒度；同分只表示评分档位未变，不能证明产物内容完全相同。两次都不合格也属于“无变化，仍失败”。
- **变坏：** 新增错误、保护项退化、质量下降或相同条件下成本增大；同时写预算是否仍满足。超过用途硬上限单列为硬回归，不能用别处涨分抵消。
- **无法判断：** 未测、证据不足、检测覆盖变化、输入/预算不等价或差异小于可辨识精度。写明缺少什么；不能当作零分变化或无回归。

先展示所有预先声明的目标、保护项、硬门槛和成本，再展示探索中新增的发现。新增发现回查基准时使用相同检测：能确认旧版没有/新版出现，才称新增回归；旧版未测不能直接声称旧版没有。

缺失值写“未知/未测”，不填 0。单位、量纲及测量范围不一致时不算百分比；基准为 0 时给绝对变化，不报无限倍提升。聚合/总分必须可追溯到逐项值，分母与未测项必须显式列出，不按总分掩盖相反变化。

### E. 收益与代价解释

分别给出：**产物差异结论、用途是否通过、Skill 修改效果能否归因**。总体“正向/负向/有条件取舍/证据不足”按 [评测规则](evaluation-policy.md) 判断，不能替代逐项四分类。

列出首轮与最近一轮的差别、修正预算、采样/审阅限制。视觉自评分不转写为测量还原率，模板存在/工具连通不写成建模能力改善；制作时间未知就不声称效率提高。

### F. 附件与待验证假设

链接运行记录、输入/输出清单、完整失败和重试、对照图、评分明细、成本与复评记录。可选提出可复用流程的待验证假设，标明尚未证实；**不要以“修好这个杯子/降低这只轮子的面数”充当测试结论或 Skill 已改善的证据。** 单次产物修复若已获授权，另记修复任务；只有新的、可比较的测试才更新效果结论。

## 5. 发布报告前的文档检查

- A–F 均已填写；不适用的栏目有理由，空模板不能算完成。
- 每轮输入/输出、实际生成/引用链、版本和证据哈希可追溯；没有把旧/新两组产物覆盖掉。
- 所有预设指标与保护项都有结果；四分类完整覆盖，不仅报告涨分项。
- 基准与候选检测范围相同；新发现与历史未测明确分开。
- 同分、未知、未运行、持续失败分别表达；总分和通过数未隐藏回归。
- 首候选与更多重试后的结果分开，预算改变不包装为同预算优化。
- 测试结论与改进动作分开，记录归因限制及下一轮要验证的流程假设。

这些是文档交付要求。现有工具仍只验证其各自覆盖的字段/检查，本规范不声称已有自动检查器能判定全部报告语义。
