# 修改收益与评测

分别评价知识准确性、检索适用性、Skill 决策过程和产物质量。技术单测不等于 Agent 效果；检索命中不等于修复成功。

比较前声明主要收益目标、严重错误和回归约束；固定任务起点、模型、工具版本、预算和评分标准。旧版/新版采用同一组任务及成对重复编号，保留未参与编写的测试集，不用调优后的案例冒充盲测。记录失败、跳过、未运行与不确定，禁止删掉失败重试后只报最后一次。

每个 task/repeat 的记录包括 status、检查明细、证据文件、耗时、上下文成本和人工介入；检查类型区分结构/行为/视觉。只有所有必需检查通过才能报 passed；严重错误必须 failed。视觉证据需固定相机、灯光、姿势和尺度并记录审阅者，评分器用正确、单项缺陷、边界和合法替代方案校准。评测工作区不能向 Agent 暴露评分答案或黄金产物。

正向：预先声明的目标改善且回归约束通过；负向：新增严重错误或损坏必要交付；有条件取舍：部分用途改善而其他用途退化，限制适用范围；证据不足：未实际运行、缺失配对、样本不足或结论不稳定。比较器仅提供保守统计建议，不自动批准发布。

仓库轻量 CI 校验索引、检索、评分格式及工具逻辑。Blender 实机与 Agent 执行独立调用，不在普通 CI 中安装 Blender 或请求模型。现有文字型 evals.json 保留，新增 task-suite.json 承载可校验检查契约。使用 tools/run_evals.py 校验/汇总外部执行记录；它不虚构 Agent 执行。使用 tools/compare_evals.py 比较两份报告。

比较策略示例在 evals/policies/success-with-cost-limits.json：声明 objective、所有成本的 max_mean_increase/max_per_run、protected_checks 与 minimum_distinct_tasks。执行前锁定策略哈希，两个运行的 metadata.comparison_policy_sha256 必须匹配；没有运行前绑定或没有观察到实际模型身份时不产生正向结论。成本目标支持耗时、上下文和人工介入；置信界仍依赖任务采样的独立性及预先声明的边界。单个车轮任务重复不能满足不同任务数量要求。

## 测试报告交付

每轮按 [测试输出文档规范 v1](test-output-standard.md) 和 [报告模板](../evals/templates/test-output.md) 交付。报告先检查实际输入、消费链及可比性，再检查实际输出，逐项展示改进、无变化、变坏与无法判断，最后讨论用途通过情况和 Skill 效果归因。总分不替代变化表，未知/未重测不算无变化。冻结报告后，若继续优化可复用流程，另立修改记录与新一轮测试；单次产物修复不追溯更新旧轮成绩。

## 建模路线的等预算对比

使用 [成对建模协议模板](../evals/templates/paired-modeling-protocol.json) 在运行前明确唯一要研究的流程变化。两组从同一原始图/起始资产和等价上下文开始，锁定实际模型、工具、评分器、图像生成额度、质量修正额度、时间/token 与交付资源上限；未完成的 draft 模板不能算冻结协议。将同一预算的规范序列化值写入现有运行记录 metadata.budget，将原始输入和比较策略绑定到现有 metadata.source_sha256 / comparison_policy_sha256，并保留实际调用轨迹供核查。

相同上限不要求强行消耗相同次数；实际使用的生成、修正及成本单独报告。首次候选和额度内修正后结果分别计分，不用额外迭代后的新版对比旧版单候选。一次性环境安装与制作成本分开，未知 token/模型身份保持未知。只要原资源硬上限失败，不能用外观涨分抵消。

分别度量“生成参考忠实度”“是否实现所选建模约束”“最终模型对原图的忠实度”。建模和评分共享一张描绘只能验证实现一致性；独立原图区域/视角审查和用途验收仍需执行。保留新对象/新视角作未见案例，真实执行遵循现有隔离、配对和策略规则。现有比较器会拒绝 budget 元数据不等，但模板本身不会自动限制调用次数；仍须核对轨迹，不能仅靠相同 budget 字符串宣称等预算执行。

报告采用 [测试输出规范](test-output-standard.md) 的四分类变化表。合法缺陷夹具被拦住只证明检查覆盖；最终产物的质量、完成率和成本收益需新的实际成对运行，保持 experimental 直到获得相应证据。
