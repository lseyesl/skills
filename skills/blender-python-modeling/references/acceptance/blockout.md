# 基础形体验收与细化前置条件

先声明用途、目标模块与控制证据，检查项由具体任务确定。至少包含实际视觉检查；物体存在、顶点数或细分等级不足以授权细化。

- 比例：尺寸、相对位置、参考关键点或已明确的设计参数。
- 轮廓/体积：必要视角、深度、厚度、主截面、负空间，不能只靠正面相似。
- 结构：部件/重复数量、对称/非对称、连接和独立关系。
- 功能：需要时检查轮轴、转向/装配间隙、关节位置和活动空间；静态雕塑不额外要求动画。
- 可细化性：当前表示是否支持下一阶段；Cube 盒式建模与基础体组合都可以合格，任意相交体不自动等于连续可变形表面。

在建模计划逐项定义结构/视觉/功能检查；review 用与计划一致的 check ID，记录 passed 状态、具体 finding、非空且哈希匹配的证据。视觉项还要标识 view，unresolved_issues 必须为空。不能因“已运行 builder”把模板 unknown 改成 passed。

证据文件相对 review JSON 所在目录，只允许其目录内的后代路径。结构测量也要保存报告；截图文件存在、哈希和状态格式一致只证明证据可追溯，工具不鉴定图片是否正确。

既有资产可以 method=reuse，保存源快照并检查实际状态后直接进入 review，不需要重建。局部修复只选择受影响模块，记录其他必要依赖；审阅后移动依赖部件、修改源网格/比例/连接/表示方法或参考会使相关回执失效。

粗模通过不等于 feature-complete/final。模板默认细化派生副本，不原地改变已审阅的粗模；精细输出后续仍需自己的视觉、形变和交付验收。对采用原地控制笼的成熟项目，必须提供等价的冻结控制状态与依赖检查，不能直接关闭前置检查。

inspection_signature 必须对应实际被检查的粗模、计划、作用域和依赖。修改形体后，仅重跑记录函数而不更新实际检查将被拒绝。每次新建草稿保留 pending/unknown，实际检查完成后才填写 passed。

计划可为模块声明 world_dimensions（整个绑定模块的世界轴对齐尺寸）和 dimension_tolerance；模板会测量实际求值几何并在超差时阻断。没有声明数值目标时不推断正确尺寸；共享网格的局部区域需项目自定义测量。默认状态/测量适配 mesh/curve，其他表示应提供等价适配器或可检查代理。
