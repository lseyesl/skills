# 任务分析

先区分 create/repair/optimize/animate/export；说明目标用途、输出阶段、平台、预算与必须保留内容。创建任务确定结构和参考，修复任务先复现，优化任务先测基线，导出任务先确认消费端契约。

项目内使用 [任务记录模板](../assets/task-analysis-template.json) 的字段创建 task-analysis.json。简单修改可只写相关字段，但必须有目标对象、事实、方案与验收；未测项用 unknown，不能写成通过。记录对象 owner/稳定 ID、名称、集合及网格/骨架/动作关联。复制原文件或保存派生文件，保留修改前签名及可恢复快照。

observations 是实际工具/截图/测量事实；hypotheses 是可证伪假设，每项给区分检查；decision 给选中知识 ID、排除方案及理由。目标容差依资产尺度、镜头和平台确定并在修改前固定。台账继续管模块完成度，stage_guard 管执行及证据新鲜度；任务记录不重复替代二者。

已有兼容资产的局部修改无需重新生成设计图。新参考驱动角色仍遵守中立姿态与参考审阅前置条件。缺失信息只阻塞依赖它的操作。

复杂新建或重大形体修改增加 modeling_plan 路径、scope 和 review_receipt；分模块选择表示方法并说明理由。复用已有资产记录来源快照与复用依据；局部修复不强制重建。模块台账仍管完成度，建模计划管方法与前置检查，不相互复制状态。

scene 记录 create/edit、明确场景和角色集合；runtime_preflight 保存实际探针记录和有效降噪设置。delivery_contract 记录静态/旋转/蒙皮模式、对象白名单、预算、帧、clip 和世界单位容差。repair_budget 在尝试前声明次数/时间；repair_attempts 逐项保存快照、观察、假设、修改、测量、视图和剩余问题，不覆盖失败。

## 新建整模的两阶段规划

接单时在任务记录的 intended_use、deliverable 和 modeling_plan.project_brief 中写明用途、交付物、参考来源、风格目标与阶段里程碑。每个里程碑说明要得到哪件可检查的产物，例如已审参考图、组装粗模、已审白模和回读后的交付模型。使用已有记录的路径关联证据。局部修改按任务范围选用相关步骤。

参考审阅、风格确认和视图校准完成后，在[建模计划](../assets/modeling-plan-template.json)列出模块及其施工前置模块，按依赖先后排列。若两个部件必须一起试配，把它们放入同一步组装检查。每个模块填写从上到下执行的 build_steps，每步用 action 写出施工动作和要装在一起看的部件，用 check_ids 指向本模块已有的通过条件、控制视角。安排每项检查的最早可判定时机；遮挡会随组装改变的项目可在后续步骤重复引用。

以交领为例，先在颈肩上裁前衣片，确认开口中露出的内层；再铺内外襟，核对正面交点与侧面领宽；装回腰带后，用同一机位复查外襟末端。脚与鞋共用足部截面，手与袖口共用腕线，头坯与头发共用发际和耳后边界。按本次参考和装配关系选择步骤。

执行时在模块台账记录当前步骤及其实查证据。对后续会被遮住的结构，在覆盖前保存本步快照与检查图；整模验收时同时查看当前组装效果和对应的过程证据。通过本步检查后开始依赖它的步骤。若失败，定位负责该形状或遮挡的模块，修正后用原相机复拍目标、邻件和受影响视角。所有模块装回后再做整模验收。参考或结构假设改变时先更新施工计划，再重验依赖旧假设的步骤。
