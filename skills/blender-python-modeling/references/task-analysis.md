# 任务分析

先区分 create/repair/optimize/animate/export；说明目标用途、输出阶段、平台、预算与必须保留内容。创建任务确定结构和参考，修复任务先复现，优化任务先测基线，导出任务先确认消费端契约。

项目内使用 [任务记录模板](../assets/task-analysis-template.json) 的字段创建 task-analysis.json。简单修改可只写相关字段，但必须有目标对象、事实、方案与验收；未测项用 unknown，不能写成通过。记录对象 owner/稳定 ID、名称、集合及网格/骨架/动作关联。复制原文件或保存派生文件，保留修改前签名及可恢复快照。

observations 是实际工具/截图/测量事实；hypotheses 是可证伪假设，每项给区分检查；decision 给选中知识 ID、排除方案及理由。目标容差依资产尺度、镜头和平台确定并在修改前固定。台账继续管模块完成度，stage_guard 管执行及证据新鲜度；任务记录不重复替代二者。

已有兼容资产的局部修改无需重新生成设计图。新参考驱动角色仍遵守中立姿态与参考审阅前置条件。缺失信息只阻塞依赖它的操作。

复杂新建或重大形体修改增加 modeling_plan 路径、scope 和 review_receipt；分模块选择表示方法并说明理由。复用已有资产记录来源快照与复用依据；局部修复不强制重建。模块台账仍管完成度，建模计划管方法与前置检查，不相互复制状态。
