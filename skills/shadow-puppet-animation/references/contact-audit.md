# 接触量测与复现测试

## 从参考到可比较片段

先以实际解码时间戳确定入点、出点和镜头切点。粗采样选段后，再检查切点前后相邻帧；场景变化检测仅提供候选，不能独立判定剪辑。记录半开时间区间与输出总帧数，避免短片尾部混入下一镜。保留基线，修订镜头时间后同步修改事件和对照视频。

区分资产来源：参考像素提取、生成式新资产、程序化替身、人工绘制。替身可以发现动作和装配问题，不能证明角色生成能力或美术达到参考。不得用原片背景或人物的直接复用，冒充独立生成的品质成果。

## 固定二维舞台的锚点检查器

`scripts/audit_contacts.py` 复用 shadow-puppet-part-splitter 的父子变换计算，检查已明确输入的每帧锚点与目标间距离。使用此工具时需有该协作技能；非标准安装位置用 `--splitter-scripts /actual/path/scripts`。它不设计动作，不求解 IK，不检测轮廓接触、穿插、物理平衡或专业审美。

输入：原生 manifest；一个 JSON 姿态数组（每项含 `frame` 及可选 `angles/translations/scales`）；一个 contact 数组。例如：

```json
[{"id":"left-foot-support","node":"foot_l","point":[100,280],
  "target":{"point":[120,280]},"frames":[12,26],"tolerance_px":0.5},
 {"id":"tray-in-hand","node":"tray","point":[175,190],
  "target":{"node":"hand","point":[175,190]},"frames":[1,90],"tolerance_px":0.5}]
```

`point` 是静止画布中的全局像素坐标，不是部件裁剪坐标。`frames` 含首尾帧；每个被检查帧必须提供姿态，稀疏关键帧会报错，不能当连续区间通过。固定目标不随 actor 根移动；移动目标由目标节点同帧变换计算。单帧接触只能证明该帧距离，不能证明支撑阶段稳定。阈值由镜头尺度和锚点用途决定。

```bash
python scripts/audit_contacts.py --manifest /project/manifest.json \
  --motion /project/poses.json --contacts /project/contacts.json \
  --output /project/qa/contact-v1.json
python tests/test_contacts.py
```

退出码：0 为声明范围内锚点通过，1 为超过容差，2 为无效输入；输出须为新文件。报告保留 `visual_review: pending`。这是固定二维坐标的量测；相机运动、透视或三维场景应由对应后端提供统一空间中的变换，不能直接解释为真实世界接触。

## 必须与量测一起检查的项目

- 脚踝锚点不等于鞋底；确认量测点落在可见鞋底，并检查脚掌角度、厚度及地面。零锚点偏差不能替代轮廓检查。
- 停步既要位置连续，也要速度合理。冻结步态可能保留两脚位置，却造成根速度突变；检查停步前后速度和重心。
- 支撑点正确而双膝持续深弯仍可能是错误步态；另对照承重腿伸展、经过姿态、鞋尖和停稳轮廓。检查上身及髋部各自的垂直范围，防止固定高度走路或把头部曲线误作髋部曲线。
- 道具与手必须比较两套实际变换，不能只检查道具是否符合自身轨迹。父子关系正确仍可能有错误的视觉握点。
- 对固定支撑不要每帧把目标更新成演员位置；那会让滑步也得到零误差。支持区间和目标应来源于独立事件计划。
- 数值改进、采样画面改进、原速审阅和音频审阅分别记录。播放器启动、解码成功或截图出现均不能自动标记“已完整观看”。

仅将真实完成的验证写入报告。保留源片段、版本化复现视频、可编辑源、事件映射、量测输入输出及未解决问题；单镜验证不扩大为整套体系或整片品质证明。
