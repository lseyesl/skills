# 图片到可用 3D：首轮探索基准

固定 Skill 版本：`b7a0844`；执行日期：2026-11-13；Blender 4.3.2 CPU。

本目录保存三类任务的输入、许可、运行前固定的 protocol/freeze、实际任务配方和技术评分器。它是**当前会话执行、同一 Agent 视觉自评的产物基准**，没有独立模型身份/用量观测，没有隔离或盲测，也没有独立视觉评分校准。不得作为正式 Agent 成功率、Skill 提升或泛化能力证据。角色是既有回归案例，复用了专用配置与注释。

静态道具为白瓷杯与瓷勺，机械件为双五辐车轮，角色要求持久骨架、形变检查与导出动画。绝对尺寸未知；照片中的隐藏几何为推断，不能称为测量还原。未提供对应目标引擎，本轮消费检查只覆盖 Blender 新场景重载和 Khronos 格式验证。

## 分数与通过条件

总分 100：参考还原 40、技术质量 20、用途与导出 25、流程证据 15。至少 80 分，同时达到各维度下限并通过所有用途硬门槛。杯子不能只有外壳；车轮不能只有圆形；角色不能只有人物外观。失败的粗模检查应阻止细化，不通过的交付不因总分较高而获得通过。

详细分值、视觉档位与未知项政策见 `protocol.json`。输入和标准在首跑前以 `freeze.json` 固定。构建配方是本轮 Agent 的执行产物，不是隐藏黄金答案；技术检查器不读取配方来判断结果。视觉自评分只作待独立复核的估计。

## 实际运行与证据

本轮原始日志与模型保留在仓库 `.tmp/image3d-baseline-20261113/`。`results/` 保存评分、技术报告、比较图和原始失败索引。完整可移植包同时包含输入、代码、报告、日志与 `.blend`/GLB；不要把 `.tmp` 路径当作永久资产服务地址。

`build_props.py` 依次支持 blockout、review（只生成待检查草稿）、refine。首轮两个道具均在实际粗模检查发现结构缺陷，`record_failed_blockouts.py` 将其记录为 failed，实测前置门禁拒绝，并只导出诊断粗模。没有运行 refine；诊断模型不是可交付的精细资产。

角色调用当前 Skill 已有 `fit_character.py build --rig-test`，因 OpenImageDenoise 不可用而中断。原始失败保留。`inspect_character.py` 仅在诊断进程禁用降噪，复用保存的几何生成检查视图；不修改 Skill 源码、不添加骨架，也不把补救算成首跑成功。该适配器输出独立存放。

`check_assets.py` 在新的 Blender 进程中重开源文件和导出文件，测量有限性、三角面、边界、导出范围、所需骨架/动作和用途检查；`calibrate_technical.py` 包含正确开放面、退化面、重命名替代、位移和静态非骨骼资产七个控制案例。它不认证解剖、汽车结构或图像相似度。Khronos 验证单独调用库内 `gltf_audit.py`。

1. 先核验 `freeze.json` 的输入与标准哈希，锁定 Skill Git 版本、运行模型、Blender、预算与执行模式。

3. 使用相同技术评分器及视觉标准，重新校准工具环境。对发生变化的评分器不能直接沿用旧分数。
4. 技术故障补救、人工介入、建模重试分别计数。此轮只测第一轮候选、不给艺术修复重试；它不能代表充分迭代后的上限。
