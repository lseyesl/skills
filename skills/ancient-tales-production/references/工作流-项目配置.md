# 项目配置与路由

配置属于具体制作项目，不在 Skill 库设置一个会影响所有故事的默认后端或视觉风格。恢复任务时读取仓库 README、项目身份与配置、生产总控、最新交接，并与真实代码和资产索引核对。

## 配置职责

| 事实 | 权威位置 |
|---|---|
| 项目与故事身份、视觉风格及版本、实现后端 | 项目锁定配置；已有工程也核对 `project.json` 或对应入口 |
| 当前阶段、上游版本和下一动作 | 本项目 `content/制作/生产总控.md` |
| 通用阶段、状态与门槛 | [全流程总控](工作流-全流程总控.md) |
| 专业产物与验收 | 下表中对应参考 |
| 二进制身份与状态 | [资产所有权](工作流-跨仓库资产所有权.md)及项目资产清单 |
| Skill 来源与必需依赖 | 项目 `skills.lock.json`，从库的 `skills.json` 解析 |
| 本机可执行文件与工作目录 | 环境变量或项目忽略的本机配置，不作为可移植资源身份 |

`project_id`、`story_id`、`visual_profile`、`visual_profile_version` 和 `implementation_profile` 是不同字段。同一故事的另一套风格建立独立项目，不覆盖原配置。缺少后端绑定时保持未绑定，不能从文件名或旧项目猜测。

## 可选资产工具路由

精灵动画、自动拆件或生成工具按镜头需求选用，在项目记录选择与交付契约；可选工具不会改变已锁定的视觉和实现绑定。依赖声明中的可选 Skill 只有实际任务需要时才显式安装。

## 视觉 profile

从项目配置读取风格与版本，按上表选择专业参考。可用 Skill 不等于项目已批准使用该风格；新增风格或混合风格需要明确设计约定与验收。

## 实现 profile

Blender、Godot 等具体后端的可执行入口以对应仓库 `docs/backend/` 和实际脚本为准。历史文档或仓库名称不能证明后端已经实现或可运行。

## 配置变更

切换风格须新建独立项目；升级同风格契约或修改实现绑定须形成明确配置版本，审计身份、资产和时间轴影响，受影响下游标为 `needs-sync`。不比较历史工作流文档版本与项目协议版本的数字来推断兼容性。
