# 中国神话视频成片合成与质量检查工作流

本流程把锁定的视频实现、语言文本、字幕和已接入音频合成为各语言终片，执行内容、视觉、声音、字幕和技术检查，完成第五个硬门槛并建立标准交付包。平台发布仍由人工完成。

上游流程：由主题锁定的[实现 profile](%E5%B7%A5%E4%BD%9C%E6%B5%81-%E9%A1%B9%E7%9B%AE%E9%85%8D%E7%BD%AE.md#%E5%AE%9E%E7%8E%B0%20profile)解析的视频实现／渲染工作流、[多语言本地化工作流](%E5%B7%A5%E4%BD%9C%E6%B5%81-%E5%A4%9A%E8%AF%AD%E8%A8%80%E6%9C%AC%E5%9C%B0%E5%8C%96.md)、[音频交付与导入工作流](%E5%B7%A5%E4%BD%9C%E6%B5%81-%E9%9F%B3%E9%A2%91%E4%BA%A4%E4%BB%98%E4%B8%8E%E5%AF%BC%E5%85%A5.md)。

总控规则：[全流程总控工作流](%E5%B7%A5%E4%BD%9C%E6%B5%81-%E5%85%A8%E6%B5%81%E7%A8%8B%E6%80%BB%E6%8E%A7.md)。

> [!important] 核心原则
> **每种语言独立合成、独立检查、独立确认。中文通过不代表英语通过；低分辨率预览通过不代表交付文件通过。**

## 默认目录

```text
projects/<project_id>/content/制作/成片/
├── delivery-manifest-v1.yaml
├── qa-summary-v1.md
├── zh-CN/
│   ├── qa-report-v1.md
│   └── render-report-v1.md
└── en-US/
    ├── qa-report-v1.md
    └── render-report-v1.md

<实际渲染输出根>/<topic-id>/<version>/<locale>/
├── <topic>_<locale>_clean_v001.mp4
├── <topic>_<locale>_subbed_v001.mp4
├── <topic>_<locale>_captions_v001.json
├── <topic>_<locale>_subtitles_v001.srt
└── <topic>_<locale>_subtitles_v001.vtt
```

Obsidian 保存记录和映射，媒体文件保存在实际视频项目的版本化输出目录。

## 正式输入

对每个 locale 必须具备：

- `locked` 视频实现母版和当前后端渲染入口；
- `locked` 本地化台本、时间轴和 locale 字幕 JSON；
- 必需音频项均为 `integrated`；
- 语言级 cue map 与混音报告；
- 输出编码、分辨率、帧率、色彩、响度和文件命名规范；
- 无字幕版、烧录字幕版和外置字幕的交付要求。

任一输入仍为占位或 `needs-sync` 时，只能输出带水印的 review 版本。

## 状态

每个 locale 的终片独立使用[总控统一状态机](%E5%B7%A5%E4%BD%9C%E6%B5%81-%E5%85%A8%E6%B5%81%E7%A8%8B%E6%80%BB%E6%8E%A7.md#%E7%BB%9F%E4%B8%80%E7%8A%B6%E6%80%81%E6%9C%BA)。全套候选生成后进入 `review`；该 locale 内容与技术检查通过后为 `approved`；交付包冻结后为 `locked`。一个 locale 通过不改变其他 locale。

## 一、预检

渲染前自动或人工确认：

- 渲染后端版本、渲染入口、locale、视频版本和输出路径正确；
- 场景 ID、文本 ID、音频 ID 无缺失或重复；
- locale 字幕 JSON 时间合法且在视频母版范围内；
- 所有资源路径存在，正式构建中没有 placeholder；
- 字体覆盖目标语言所需字符；
- clean 版本不加载烧录字幕层；
- subbed 版本加载正确 locale 字幕；
- 音频轨与该 locale 的 cue map、timeline 一致；
- 输出不会覆盖已锁定交付。

## 二、代表片段检查

全片渲染前先检查：

- 片头／第一句；
- 对白最密集处；
- 最长字幕与特殊字符；
- 音乐／音效转折最复杂处；
- 最安静和最响的段落；
- 关键事实标识与改编标识；
- 片尾与最后一个音频尾音。

代表片段失败时先修复根因，不继续用完整渲染掩盖问题。

## 三、生成候选终片

每个 locale 至少生成：

1. `clean`：包含本语言配音／混音，不烧录对话字幕；
2. `subbed`：与 clean 相同，额外烧录本语言字幕；
3. `captions.json`：内部 locale 字幕数据；
4. `subtitles.srt`；
5. `subtitles.vtt`。

如果画面内存在剧情必要的标题、来源和改编标识，它们属于本地化屏幕文字，不因 clean 版本而消失。clean 只表示不烧录对话／旁白字幕。

## 四、内容 QA

- 镜头顺序、故事事实、人物关系和核心因果与锁定母版一致；
- A／B／C／D 证据边界仍被正确表达；
- 原典、来源、研究归属和改编标识在正确时机出现；
- 没有缺镜、黑帧、临时卡、测试文字或错误资产；
- 每个必要文本单元在画面、口播或字幕中得到正确承载；
- 片头、章节、片尾和署名使用正确版本。

## 五、语言与字幕 QA

- 音轨、屏幕文字和字幕都是目标 locale；
- 台词与锁定本地化台本一致；
- 专名、称谓、数字和语气正确；
- 字幕无错字、乱码、截断、过早出现或延迟消失；
- 字幕断句自然，阅读速度可接受；
- 字幕位于安全区，不遮挡关键角色、来源或改编标识；
- 字体、字号、方向、标点和换行适合该 locale；
- Caption JSON、SRT、VTT 与烧录字幕内容和时间一致。

## 六、音频 QA

- 配音完整，无错行、重复、截尾、爆音和异常底噪；
- 角色音色、距离、表演和录音环境连续；
- 音乐与音效按该 locale 的语言节奏进入和退出；
- 人声清晰，ducking 没有抽吸或突然跳变；
- 关键叙事音效可辨识，不遮蔽关键台词；
- 静默段没有意外噪声；
- 头尾没有点击、截断或多余长静音；
- 集成响度、动态范围和 true peak 符合已记录的目标平台规范。

## 七、视觉与时间 QA

- 构图、动作、遮挡、锚点和转场无跳变；
- locked 元素展现表中的事件链、交互结果、退场／恢复、结束状态和跨镜交接在完整成片中没有被删减或改序；
- 受力、惯性、重力、流体方向、减速和回落符合导演设定的最低可信规则；持续环境系统方向一致、接续无明显循环断点，不以原地晃动冒充流动；
- 主体、次要动作与环境层的注意力接力清楚，没有因本地化、字幕或音频重定时导致焦点冲突；
- locale 时间伸缩没有造成动作停滞、重复帧或不合理加速；
- 旁白／对白与对应画面语义同步；
- 字幕与口播同步；
- 画面内本地化文字没有溢出、挤压或破坏构图；
- 连续性、闪烁、抖动、透明边缘和色带问题已检查；
- 第一帧、最后一帧和章节边界完整。

上述技术与制作检查完成后，导演必须对目标 locale 的完整连续成片独立签署：叙事、表演、构图、镜头节奏、连续性、信息密度和音画关系均为 `pass`。导演签署不能由抽帧、局部片段、自动 QA 或用户对单一效果的确认代替。

## 八、技术 QA

对实际交付文件检查并记录：

| 项目 | 记录 |
|---|---|
| 文件名／路径 | locale、版本和变体正确 |
| 容器／编解码 | 与交付规格一致 |
| 分辨率／画幅 | 与视频母版和平台要求一致 |
| 帧率／总帧数 | 固定且与时间轴一致 |
| 时长 | 视频、音频和字幕范围一致 |
| 音频 | 采样率、声道和流存在 |
| 色彩 | 无错误 gamma／色偏，必要时记录色彩空间 |
| 文件完整性 | 可从头到尾解码，无损坏 |
| 校验值 | SHA-256 或项目约定值 |
| 文件大小 | 已记录且符合上传边界 |

只看播放器能打开，不等于技术 QA 通过。

## 九、问题分级与返修

| 级别 | 示例 | 处理 |
|---|---|---|
| blocker | 错语言、缺音轨、文件损坏、事实错误、缺镜 | 禁止确认 |
| major | 错译、明显不同步、字幕遮挡、持续削波 | 修复后重检受影响段及全片抽检 |
| minor | 单处标点、轻微非关键视觉瑕疵 | 记录并由确认者决定是否阻塞 |

每条问题至少记录：问题 ID、locale、版本、时间码、镜号／text ID、严重级别、证据、责任阶段、修复版本和复检结果。

上游问题退回对应工作流，不能只在终片上打补丁：

- 事实或台词：编剧／本地化；
- 镜头或动作：导演／视频实现；
- 视觉资产：美术；
- 配音／音乐／音效：音频；
- 字幕时间：本地化；
- 编码或渲染：视频实现。

## 十、门槛五：各语言终片确认

每个 locale 单独满足：

- clean、subbed、Caption JSON、SRT、VTT 全部存在；
- 内容、语言、字幕、音频、视觉、时间和技术 QA 通过；
- blocker 和 major 为零；
- minor 已明确接受或修复；
- 导演已对该 locale 完整终片给出 `pass`，并写入 QA 报告与生产总控页；
- 用户或授权确认者完成该 locale 审阅；
- `qa-report`、`render-report` 和 delivery manifest 完整；
- 文件版本和校验值冻结。

确认后先设为 `approved`；写入确认人和日期，建立不可覆盖的交付目录后设为 `locked`。未确认 locale 保持自身状态，不影响已锁定语言版本。

## 十一、交付清单

`delivery-manifest-v1.yaml` 至少记录：

```yaml
topic: <主题>
version: v1
video_master: "[[<锁定视频实现>]]"
locales:
  zh-CN:
    status: locked
    timeline_version: v1
    audio_version: v1
    clean:
      path: <文件路径>
      sha256: <校验值>
    subbed:
      path: <文件路径>
      sha256: <校验值>
    captions_json: <文件路径>
    srt: <文件路径>
    vtt: <文件路径>
    qa_report: "[[<QA 报告>]]"
    director_review_status: pass
    director_reviewed_at: <日期>
    approved_at: <日期>
    approved_by: <确认者>
```

新增语言只增加 locale 节点，不覆盖既有语言交付。

## 十二、人工发布交接

系统交付：

- 版本化媒体和字幕文件；
- delivery manifest、校验值和 QA 报告；
- 标题、封面、简介、来源和署名的建议或草稿（如另有制作）；
- 已知平台限制和未决 minor 问题。

人工负责：

- 选择最终上传文件；
- 在平台填写信息、上传、设置语言／字幕和发布时间；
- 完成平台侧预览；
- 发布与发布后数据复盘。

不得把“交付包已锁定”写成“已发布”。

## 完成检查

- [ ] 每个 locale 都绑定具体的视频、语言、字幕和音频版本。
- [ ] clean、subbed、Caption JSON、SRT、VTT 全部生成。
- [ ] 正式构建没有 placeholder、测试文字或缺失资源。
- [ ] 内容、语言、字幕、音频、视觉、时间和技术 QA 均有记录。
- [ ] 导演已在完整连续成片中复核元素事件链、交互因果、运动可信度、状态连续性、注意力接力和环境循环。
- [ ] blocker／major 已清零。
- [ ] 导演已对每个待确认 locale 的完整连续终片签署 `pass`，并同步生产总控页。
- [ ] 各语言独立确认，没有用中文结果替代其他语言验收。
- [ ] delivery manifest 含路径、版本、校验值和确认记录。
- [ ] 人工发布边界保持清楚。
