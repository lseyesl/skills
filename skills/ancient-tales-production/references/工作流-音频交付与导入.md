# 中国神话视频音频交付与导入工作流

本流程先把配音、音乐、音效和环境声写成可交付要求，待真实文件提供后再完成接收、质检、映射、同步和语言级混音。它不把需求文档、占位音或文件名当作真实音频完成。

上游流程：[多语言本地化工作流](%E5%B7%A5%E4%BD%9C%E6%B5%81-%E5%A4%9A%E8%AF%AD%E8%A8%80%E6%9C%AC%E5%9C%B0%E5%8C%96.md)、[导演工作流](%E5%B7%A5%E4%BD%9C%E6%B5%81-%E5%AF%BC%E6%BC%94.md)。

下游流程：[成片合成与质量检查工作流](%E5%B7%A5%E4%BD%9C%E6%B5%81-%E6%88%90%E7%89%87%E5%90%88%E6%88%90%E4%B8%8E%E8%B4%A8%E9%87%8F%E6%A3%80%E6%9F%A5.md)。

> [!important] 核心原则
> **音频要求、收到的源文件、通过质检的文件和已接入混音是四种不同状态。共享素材不等于共享混音。**

## 默认目录

```text
projects/<project_id>/content/制作/音频/
├── audio-requirements-v1.md
├── audio-manifest-v1.yaml
├── shared/
│   ├── music/
│   ├── sfx/
│   └── ambience/
├── zh-CN/
│   ├── voice/
│   ├── cue-map-v1.json
│   └── mix-report-v1.md
└── en-US/
    ├── voice/
    ├── cue-map-v1.json
    └── mix-report-v1.md
```

实际媒体文件保存在版本化音频交付区；Obsidian manifest 记录收到的源文件、版本和校验结果。主题实现配置从[项目配置](%E5%B7%A5%E4%BD%9C%E6%B5%81-%E9%A1%B9%E7%9B%AE%E9%85%8D%E7%BD%AE.md#%E5%AE%9E%E7%8E%B0%20profile)解析，其资源路径由平台实现记录维护，不写回平台无关音频 manifest。

## 输入

- `locked` 的 locale 台本和文本单元表；
- 对应 locale 的时间轴与 Caption JSON；
- `locked` 分镜中的声音要求；
- 主题音乐与音效 cue 表；
- 视频母版、帧率、画幅、目标平台和响度规范；
- 已有音频资产的来源、授权和使用范围。

## 状态

单个音频项使用：

| 状态 | 含义 |
|---|---|
| `requested` | 要求已定义，文件尚未提供 |
| `received` | 文件已收到，尚未完成质检 |
| `validated` | 格式、内容、权利和听感检查通过 |
| `integrated` | 已映射到具体语言时间轴并完成预览 |
| `rejected` | 文件错误、损坏、错读或不符合要求 |
| `needs-sync` | 台本、时间轴、cue 或视频版本变化 |

阶段文档仍使用总控的 `draft/review/approved/locked/blocked/needs-sync`。

## 一、音频需求单

在音频文件到达前，先建立需求，不生成虚假路径。

### 配音要求

每条配音绑定：

- locale；
- `text_id`；
- speaker／角色；
- 锁定台词；
- 发音、情绪、语速、停顿和重音；
- 预计时长与可伸缩范围；
- 是否需要 breaths／efforts／呼喊等非文字表演；
- 文件格式和命名；
- 版本与交付状态。

建议命名：

```text
VO_<locale>_<speaker>_<text-id>_v001.wav
```

文件名中的 locale 和 text ID 不得省略；台词变化时递增版本，不覆盖旧录音。

### 音乐要求

记录：

- cue ID、主题、情绪、段落功能；
- 进入、退出、循环、尾奏和可剪辑点；
- 是否需要分轨或 stem；
- 许可范围、来源、署名和期限；
- 共享源文件及每种语言的音量／时机覆盖。

### 音效与环境声要求

记录：

- cue ID、对应镜号和叙事作用；
- 触发动作、预期时长、空间位置和远近；
- 可否循环、是否需要变体；
- 与对白竞争时的让位规则；
- 来源、授权和文件版本。

## 二、技术交付规格

实际规格以制作约定为准，并写进需求单。没有其他约定时可采用：

| 类型 | 建议源文件 |
|---|---|
| 配音 | WAV，48 kHz，24-bit，mono，干声 |
| 音乐 | WAV，48 kHz，24-bit，stereo；需要时附 stems |
| 音效／环境 | WAV，48 kHz，24-bit；按素材空间需求 mono／stereo |

要求：

- 不在源文件上叠加不可逆总线限制、混响或背景音乐；
- 文件开头和结尾保留合理余量；
- 不裁掉辅音、呼吸或自然尾音；
- 交付清单记录峰值、底噪、声道、时长和授权；
- 目标响度与 true peak 由目标平台和最终混音规范决定，不用单条文件冒充终片达标。

## 三、接收与质检

收到每个文件后检查：

### 文件级

- 文件存在、可读取、未损坏；
- 文件名、locale、speaker、text ID 和版本匹配；
- 采样率、位深、声道和时长符合要求；
- 无削波、明显爆音、丢帧、异常静音或截尾；
- 来源、授权和交付者记录完整。

### 配音内容

- 台词与锁定 locale 台本一致；
- 专名、数字、古籍名和称谓读音正确；
- 角色身份、情绪、重音和语速符合要求；
- 没有把表演备注、标点说明或不可口播文字读出；
- 同一角色跨行音色、距离和录音环境连续。

### 音乐与音效

- cue 功能、长度和可剪辑点可用；
- 循环无明显接缝；
- 关键叙事音效可辨识；
- 不含未经登记的水印、对白或第三方内容；
- 共享资产的使用权覆盖全部目标语言版本。

失败项设为 `rejected`，保留原因并请求新版本；不得静默修成另一个文件后沿用旧版本号。

## 四、manifest 与路径映射

`audio-manifest-v1.yaml` 至少包含：

```yaml
topic: <主题>
version: v1
video_master: "[[<视频实现版本>]]"
localization_manifest: "[[<language manifest>]]"
assets:
  - audio_id: VO-en-US-narrator-YW-01-N01
    kind: voice
    locale: en-US
    text_id: YW-01-N01
    source_path: <收到的源文件>
    platform_mapping_record:
    status: received
    rights: pending
    duration_ms:
    checksum:
```

同一真实文件只能有一个权威 `audio_id`；复制到实现目录时保留来源映射和校验值。

## 五、语言级 cue map

音乐和音效源可以共享，但每种语言建立独立 `cue-map`：

```json
{
  "locale": "en-US",
  "timelineVersion": "v1",
  "cues": [
    {
      "cueId": "MUS-FOREST-01",
      "audioId": "MUS-FOREST-MASTER-v001",
      "sceneIds": ["JY-01", "JY-02"],
      "startMs": 1200,
      "endMs": 18400,
      "gainDb": -12,
      "fadeInMs": 800,
      "fadeOutMs": 1200,
      "duckUnderTextIds": ["JY-01-N01"]
    }
  ]
}
```

原因：

- 不同语言的句长和停顿不同；
- 关键音效必须避让该语言的对白；
- 音乐转折需落在对应语言的叙事转折上；
- 同一共享文件不代表相同起止点和增益。

## 六、导入与同步

按 locale 逐个处理：

1. 校验 manifest 中所有必需项为 `validated`；
2. 复制或映射文件到实现目录；
3. 由 `text_id` 绑定配音，由 `cue_id` 绑定音乐／音效；
4. 使用真实配音时长替换试读时间；
5. 更新 locale timeline 和 Caption JSON；
6. 调整允许伸缩的镜头保持、转场和静默；
7. 检查每条配音起止、字幕同步和镜头边界；
8. 生成语言级预览；
9. 通过后将音频项设为 `integrated`。

不得通过改文件名来掩盖 text ID 错配，也不得靠固定帧偏移补偿整条时间轴的累积误差。

## 七、混音

每个 locale 独立建立混音报告。默认层级：

1. 对白／旁白；
2. 关键叙事音效；
3. 音乐；
4. 环境声；
5. 氛围底音。

检查：

- 人声始终清晰，音乐和环境声按文本单元 duck；
- 关键叙事音效既可辨识又不遮蔽语言；
- 跨镜环境、空间感和角色距离连续；
- 静默是设计结果，不是缺文件；
- 头尾、转场和循环无爆点；
- 根据目标平台记录集成响度、动态范围、true peak 和测量工具；
- 不同 locale 可以有不同自动化曲线，但应保持相同叙事意图。

## 八、导演音频后复审

真实配音、音乐和音效完成集成后，每个 locale 必须生成带当前画面、字幕和混音的连续预览，由导演复审：

- 台词是否在镜头内自然完成，动作是否具有准备、发生和结果；
- 旁白停顿、重要静默、转场和音乐落点是否符合导演母版；
- 时间伸缩是否造成画面停滞、动作循环、重复帧或不合理加速；
- 音效是否强化正确动作，音乐是否抢夺叙事焦点；
- locale 差异是否保持相同导演意图。

导演结论记录为 `pass`、`changes-requested` 或 `blocked`，并同步 `生产总控.md`。导演未 `pass` 时，该 locale 时间轴、cue map 和混音报告不得锁定，也不得进入终片 QA。

## 九、缺失音频与占位规则

- `requested` 项可以使用明确标记的占位音做技术测试；
- 占位音不得进入正式交付；
- 预览画面必须标明 locale、占位状态和缺失项；
- 缺少必需配音时，该 locale 不得进入终片确认；
- 缺少非关键环境层时可记录为风险，但是否阻塞由导演／声音验收决定；
- 系统只能声明“要求已给出”或“文件已导入”，不能把两者混称为“音频完成”。

## 十、变更控制

| 变化 | 处理 |
|---|---|
| 单句重录 | 新配音版本，重定时该 text ID 和邻接 cue |
| locale 台词改变 | 对应配音失效，字幕与混音标 `needs-sync` |
| 镜头时长改变 | 受影响 cue map 和字幕重检 |
| 共享音乐／音效替换 | 所有使用该 audio ID 的 locale 重检 |
| 只改某 locale 的 gain | 只更新该 locale mix 版本 |

## 完成检查

- [ ] 所有音频要求有唯一 ID、版本、状态和责任来源。
- [ ] 未收到的文件保持 `requested`，没有虚构完成状态。
- [ ] 配音按 locale、speaker 和 text ID 交付。
- [ ] 共享音乐／音效有权利记录，各 locale 有独立 cue map。
- [ ] 所有正式接入文件已经过技术、内容和听感检查。
- [ ] 真实配音时长已回写语言时间轴与字幕。
- [ ] 每个 locale 有独立混音报告。
- [ ] 每个 locale 的真实音频后预览已经导演复审并记录 `pass`。
- [ ] 占位音没有进入正式交付。
