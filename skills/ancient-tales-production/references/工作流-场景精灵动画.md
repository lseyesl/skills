# 中国神话视频场景精灵动画工作流

本页负责按镜头需求可选使用 `sprite-gen`，生成角色、异兽、道具或环境特效的透明精灵动画，交给主题绑定的 Godot 或 Blender 合成相应镜头。启用范围见[项目配置](%E5%B7%A5%E4%BD%9C%E6%B5%81-%E9%A1%B9%E7%9B%AE%E9%85%8D%E7%BD%AE.md#%E5%8F%AF%E9%80%89%E8%B5%84%E4%BA%A7%E5%B7%A5%E5%85%B7%E8%B7%AF%E7%94%B1)；本页不是新的视觉风格或实现后端。

## 在生产链中的位置

分镜明确动作与时间 → 镜头素材规划逐项选择实现方式 → 锁定视觉定义与动作契约 → 素材阶段执行 sprite-gen 并完成动作 QA → 输出可装配镜头素材包 → Blender／Godot 组装、时间线与视频输出 → 真实镜头审阅。

每镜的素材选择和交付要求以[镜头素材规划与输出](%E5%B7%A5%E4%BD%9C%E6%B5%81-%E7%BE%8E%E6%9C%AF%E8%AE%BE%E8%AE%A1%E4%B8%8E%E8%B5%84%E4%BA%A7.md#%E9%95%9C%E5%A4%B4%E7%B4%A0%E6%9D%90%E8%A7%84%E5%88%92%E4%B8%8E%E8%BE%93%E5%87%BA)为准。sprite-gen 的配置与生成属于素材阶段；即使文件直接写在后端仓库，也不意味着把动作设计推迟到镜头组装阶段。

上游为[美术设计与资产](%E5%B7%A5%E4%BD%9C%E6%B5%81-%E7%BE%8E%E6%9C%AF%E8%AE%BE%E8%AE%A1%E4%B8%8E%E8%B5%84%E4%BA%A7.md)和主题视觉 profile 的资产契约；下游仍为[Godot](https://github.com/lseyesl/ancient-tales-godot/blob/main/docs/backend/README.md)或[Blender](https://github.com/lseyesl/ancient-tales-blender/blob/main/docs/backend/README.md)的资源、样片与逐镜实现阶段。状态、批准和 Gate 只按[全流程总控](%E5%B7%A5%E4%BD%9C%E6%B5%81-%E5%85%A8%E6%B5%81%E7%A8%8B%E6%80%BB%E6%8E%A7.md)执行；生成成功或精灵预览通过不代表 Gate 4 通过。

## 选择是否使用

| 镜头需求 | 建议 |
|---|---|
| 固定视角的飞鸟振翅、角色短动作、火焰、浪花、烟尘等局部动画 | 可使用；先明确动作状态、空间范围和前后景关系 |
| 同一动作需要反复播放 | 可生成循环，验收首尾姿态、速度和亮度连续性 |
| 投掷、落地、破碎等一次性事件 | 生成单次动作，绑定起势、接触、峰值和结束；不自动循环 |
| 大幅绕拍、真实立体转身、复杂肢体接触或持续可编辑表演 | 优先现有 rig／三维方案；精灵只承担适合的局部效果 |

精灵不是像素画的同义词。提示词必须服从当前锁定的视觉身份、材质、轮廓、比例、光向与色板。已选 sprite-gen 的动作不得再由后端叠加同一肢体运动；位移、相机和层间遮挡由镜头合成控制，并在契约中区分已烘焙运动与后端运动。

## 镜头与资产契约

在既有 `projects/<project_id>/content/素材清单/视觉资源需求-v<版本>.md` 完成全部镜头的素材方式登记，本页处理其中已选用精灵动画的条目；完整提示词放入 `视觉设计/提示词/`，动作契约可放入 `视觉设计/场景精灵动画契约-v<版本>.md`。沿用现有主题文件优先，不建立重复状态台账。

每个动画至少明确以下内容；这些是交接要求，不宣称现有引擎 manifest 已支持同名字段：

| 内容 | 必填约定 |
|---|---|
| 身份与上游 | project_id、story_id、视觉 profile／版本、asset_id／版本、prompt_id／版本、具体 locked 分镜与视觉定义 |
| 镜头用途 | 镜号、主体、动作／方向、前中后景、遮挡对象、相机视角、屏幕尺度 |
| 动作边界 | 起始与结束姿态、关键事件、循环或单次、停止后隐藏／保持末帧、是否允许镜像和变速 |
| 时间 | 镜头 fps、入点／出点帧及区间约定、播放顺序、逐帧 durations_ms、循环次数／相位、动作事件对应镜头帧 |
| 图像 | 透明 PNG、统一画布宽高、安全边距、色彩空间、Alpha 解释、过滤方式、源尺寸与最大显示尺寸 |
| 对齐 | 统一锚点坐标及原点方向、地面／接触点、裁切偏移；不可逐帧自动居中造成滑动 |
| 运动分工 | 原地动作或含位移、哪些运动已烘焙、哪些由引擎驱动、局部层与整体位置的关系 |
| 溯源 | 基底参考身份／哈希、生成工具版本、provider、motion method、有效参数、权利边界与输出文件哈希 |

将源帧时长映射到镜头帧时，以累计时间计算边界，记录舍入、重复帧或采样规则，避免逐帧舍入累积漂移。单次动作不能为凑时长擅自循环；动作时长不匹配时按契约调整或返修，影响锁定节拍则退回导演。

## sprite-gen 执行

执行时读取用户指定或当前安装的 `sprite-gen/SKILL.md`，再读其 `docs/user-workflow.md`。本次接入依据为 sprite-gen 2.1.0；安装路径是环境信息，不是生产资产身份。`SPRITE_GEN_ROOT` 指向实际安装仓库，所有命令使用其 `.venv/bin/sprite-gen`；缺少 venv 时按技能修复或报告，不能改用任意全局 Python。

```bash
"$SPRITE_GEN_ROOT/.venv/bin/sprite-gen" workflow --kind sprite
```

1. 向只读 guide 传入用户已给出的选择或已有基底；按返回的缺项处理，沿用已授权选择，不重复询问。provider、账户访问、API 计费、默认偏好和 finish 行为以技能文档为准；不能因某 provider 不可用就自动切换。
2. 将镜头契约转为完整提示词，先锁定同项目、同风格基底，再生成动作。候选变体与正式送审绑定按[候选提示词与正式绑定](%E5%B7%A5%E4%BD%9C%E6%B5%81-%E8%B7%A8%E4%BB%93%E5%BA%93%E8%B5%84%E4%BA%A7%E6%89%80%E6%9C%89%E6%9D%83.md#%E5%80%99%E9%80%89%E6%8F%90%E7%A4%BA%E8%AF%8D%E4%B8%8E%E6%AD%A3%E5%BC%8F%E7%BB%91%E5%AE%9A)执行。已有合规基底可跳过基础图生成。
3. guide 返回 ready 后执行对应管线，并显式传入解析后的 provider。GPT 图像动作使用 `docs/atlas-workflow.md` 的 row／component extraction 管线；Grok 视频动作使用 `docs/video-pipeline.md` 的 `video-set` 管线。
4. 使用技能现有去底、提取、对齐、compose、预览与 QA；不以一次性网格生成、固定格裁切或临时裁图脚本替代规范精灵生成管线。外部已有图集的导入另按技能的 sheet-slicing 文档处理。
5. 按该管线导出最终选帧。交接透明 PNG 序列，或透明图集加每帧矩形、顺序和时长；保留 run manifest 与选择记录。命令参数以安装版本的帮助及文档为准，不假设两条管线输出目录完全相同。
6. 先交付检查后的文件，再执行 guide 的 finish 阶段；curation 视图可选，保存默认值需要用户已明确同意。重新选帧后重新导出并核对哈希与时长。

`export-aseprite` 只提供兼容 JSON，不生成可编辑的 `.aseprite` 文件；当前技能的 engine-export 文档针对 Phaser／Flame，不代表已经具备 Godot／Blender 原生导入器。GIF／WebP 作为预览；正式镜头优先消费透明 PNG 序列或图集及时间元数据。

## 所有权与交付包

生成前按[跨仓库资产所有权](%E5%B7%A5%E4%BD%9C%E6%B5%81-%E8%B7%A8%E4%BB%93%E5%BA%93%E8%B5%84%E4%BA%A7%E6%89%80%E6%9C%89%E6%9D%83.md)核对目标仓库、局部规则与授权范围。生产 run、原始生成证据、最终 PNG、图集、manifest 和引擎适配文件直接放在目标实现仓库的稳定版本路径，建议采用现有资产根下 `items/<asset_id>/<version>/source/` 和 `runtime/`；具体布局服从后端规则。审阅证据进入其 audit 根。

项目内容区 只记录提示词、动作契约和外部资源引用，不先在 项目内容区 生成生产图片再复制。纯文档检查缓存可放 项目内容区 `.tmp/`。同时服务两种后端的共享母件按所有权流程使用独立共享资产仓库，不能让一个后端成为另一个后端的隐式上游。

最小交付包包含：镜号与素材 ID 映射、镜头入出点与事件帧、最终透明帧／图集、最终播放顺序与时长、画布与锚点信息、来源与生成参数、逐文件哈希、连续动作预览及 QA 结论。素材阶段完成这些输出并按既有规则验收锁定，再作为镜头素材包的一部分交给后端。sprite-gen 原始 manifest 保留；后端映射另行维护并引用它，不能伪装成后端原生 manifest。正式锁定引用使用 repository_id、project_id、资源版本、仓库相对路径、bucket URI 和 SHA-256。

## Godot 镜头接入

1. 使用当前仓库验证过的适配方式，从最终序列或图集创建 `SpriteFrames`；图集按 manifest 的实际矩形映射为 `AtlasTexture`，不能假设等格排列或文件名排序就是播放顺序。
2. 可用 `AnimatedSprite2D` 播放独立精灵；如需沿用现有 `Sprite2D` 节点契约，则由 `AnimationPlayer` 或确定性采样器切换纹理／区域。新增节点类型需先在目标仓库实现并验证契约，不宣称已有自动支持。
3. 保留父级 `Node2D` 控制位置／旋转／缩放的分工，将统一锚点转换为精灵 offset。设置纹理过滤、层级、遮挡与透明边缘处理，并用实际显示尺度检查。
4. 将逐帧毫秒时长正确换算为 `SpriteFrames` 的相对 duration 与播放速度，或直接按镜头时间采样。离线渲染由镜头帧号确定源帧、循环相位及结束行为，不依赖实时 delta 或 autoplay 启动时刻。
5. 在真实镜头中验证随机跳帧、重播、接触帧、进出点、循环接缝及最终帧输出，再进入 Godot 主流程的样片审阅。

## Blender 镜头接入

1. 优先把最终透明 PNG 序列作为图像序列材质放在平面上，用于 2D／2.5D 镜头；仅需屏幕叠加时可选合成器或序列编辑器。选择服从镜头的景深、遮挡、相机和灯光需求。
2. 由主工作流登记的外部 Python 脚本创建平面／材质／时间映射，保留 generated／protected 数据块边界；使用相对资源路径，并记录 Blender 版本和色彩管理。
3. 非等时长源帧不能直接按每帧一张等速播放。按契约生成镜头帧到源帧的映射，必要时确定性派生等 fps 序列，保留来源映射、帧数和哈希；如消费图集则显式生成 UV 矩形映射。
4. 设置画布比例、平面锚点、Alpha 材质、深度与遮挡。依镜头选择受光材质或发光材质；已烘焙光影需避免二次照明。检查透明排序、边缘色污染、景深与运动模糊是否符合视觉定义。
5. 绑定起始帧、帧范围、循环／末帧策略；通过直接定位首帧、接触帧、末帧和连续短片验证时间映射。精灵平面不具备真实体积，大幅绕拍需求应回到既有三维／rig 方案。

## 验收与返修

- 文件：Alpha 有效、帧数与映射完整、无缺帧、画布一致、源与导出哈希可追溯。
- 视觉：同一身份与风格、无轮廓跳变／多肢／缺件、无底色残留、边缘无光晕、动作不越出画布。
- 动作：锚点稳定、接触不滑动、位移没有重复叠加、循环接缝连续、单次动作结束正确、时长和事件点对齐。
- 镜头：在真实 Godot／Blender 输出中检查前后景、相机运动、合成尺度、遮挡、首尾帧和连续播放；精灵单独预览不能替代镜头验收。
- 验证：复用后端聚合入口并确认实际覆盖精灵资源和镜头；新增适配未被检查器覆盖时如实记录并补齐验证，不把结构 pass 当视觉通过。

身份／动作像素问题退回提示词和精灵生成；锚点／采样／材质／遮挡问题在后端修复；镜号、节奏或因果变化退回导演。批准、锁定及提交继续按总控和资产所有权规则执行。
