# 皮影素材、动作与连续预览

从已选角色参考和镜头行为出发，在目标实现仓库持续完成必要素材、动作、连续预览与局部返修。先让代表行为成立，再扩展资产能力；不等待全角色拆件、完整动作覆盖或逐层人工确认才开始试动。

上游：[美术设计与资产](工作流-美术设计与资产.md)、[皮影视觉定义](工作流-皮影角色视觉定义.md)。实际处理复用 [shadow-puppet-part-splitter](../../shadow-puppet-part-splitter/SKILL.md)；项目后端入口以项目 `docs/backend/` 和真实代码为准。

## 制作方式

在已有镜头记录／资产 manifest 中简记行为、画面尺度、身份不变量、接触与起止状态。没有必要另建组件树、每层提示词文档、动作覆盖矩阵和审批单。正式上游沿用已锁定版本；探索和返修使用候选，不修改批准事实。

同一个执行者负责把素材和动作做到连续可看；职责可兼任，不要求多个 Agent。遇到遮罩、锚点或轨迹缺失时继续制作这些输入，不能只把任务转交给下一个角色。导演按完整播放结果给出具体问题，执行者就地返修，不对每张中间图停下来请求批准。

## 1. 选择代表行为与表达方法

从实际镜头选择最有信息量或风险的行为，例如衔取后起飞、抬手触物、走到座位坐下。整片剩余动作保留在原需求中，但不要求第一轮全部制作。

| 画面需求 | 先尝试 |
|---|---|
| 远景飞过／移动、静态角色 | 完整角色图与整体轨迹 |
| 简单转头、摆臂、振翅 | 少量刚性分件 |
| 张喙、握持、姿态轮廓变化 | 同锚点完整姿态或局部替换 |
| 宽袖弯曲、近景复杂表演 | 局部形变、专用姿态或更完整绑定 |

可以混用方法。骨架与服装分离只用于实际换装或独立运动需要；动物和植物也不默认套用完整运动链。已有参考图优先复用，不为流程完整重做设计。方法是否可用要核对运行时真实能力；通用二维工具不实现动态换图、换父级或网格形变，选择这些方法时须由项目脚本／运行时落实。

## 2. 做最少素材，立即装配

- 完整可见区域先裁切／蒙版提取；仅独立运动、接触或暴露的边界才拆开。
- 大块图有助于归属判断时使用，简单角色可直接提取需要的少量部件，不强制 whole → major → leaf 的逐层生成。
- 输出实际独立 RGBA PNG，逐件检查轮廓、细边、镂空与兄弟件残片。单张拼版不算资产。
- 为当前动作确定锚点、层序、搭接与接触点，在目标画幅和实际尺度下回组，不只看放大拆件图。
- 局部生成时提供完整身份参考、所改区域与邻接关系；保留可见像素，生成只处理缺失区域，不因格式统一重生成已有可用件。
- 连接材料保持连续。新制作的连接片不预打安装孔；需要可见图钉时复用独立装配外观件。已有参考中的铆钉按实际归属处理，不为这一规则无条件重画整个人物。

### 隐藏区域

皮影常规制作使用 `inferred-repair`：允许补当前动作必需的隐藏搭接，不要求先生成全套状态概念图。实际补全 mask 随资产保存，在原 manifest 标明推测；同时检查原姿态、运动暴露与可见区保护。不新增专门的策略审批文件。

项目明确要求 `concept-covered` 或传统严格复原时保留该策略：缺少依据只阻断相关区域／动作，先定位缺口再补参考。改变核心轮廓、身份、可见纹样或用户指定造型仍回视觉定义返修，不以“隐藏修补”名义改设计。

## 3. 动作与连续预览一起制作

先设计整体路径、速度、接触、主要姿态和停稳，再添加局部摆动与延迟。禁止仅写“fly／walk／sit”名称、套同相位正弦或做无意义翻面来冒充动作。

- 飞行：整体轨迹、起落与扑动节奏相配，当前镜头不需要的脚爪和翼段不额外制作。
- 衔取／握持：观察 → 接近 → 接触 → 携带／释放；物品在接触段跟随夹持点，转换时无跳变。
- 行走／坐下：按镜头所见验证根位移、重心、足底支撑与承托，不把关节旋转当作行为完成。
- 次级运动只强化主动作；动作频率、幅度和停顿服务观看尺度，不能靠粒子、光晕或相机晃动掩盖失败。

使用同一份素材和 `motion_plan.json`／项目动作脚本反复出片。二维明确轨迹可直接运行：

```bash
python <splitter-dir>/scripts/toolbox.py animate --manifest <asset-dir>/manifest.json --motion-plan <asset-dir>/motion_plan.json --output <asset-dir>/preview/v1
```

命令生成逐帧 PNG、连续 GIF 与联系表；可加入 `--stage` 同画幅场景底图。默认不要求 Blender 或 FFmpeg，具体格式和限制见 [工具说明](../../shadow-puppet-part-splitter/references/tools.md)。Pillow 预览不证明目标引擎渲染已通过；涉及灯光、形变或动态遮挡时，继续在真实运行时以相同片段验证。

## 4. 看连续结果，局部修复

先按目标速度完整播放，再查接触帧、极值、中间帧与循环边界。判断行为是否无需标签即可读懂，轮廓是否清楚，起止是否成立，接触和重心是否可信，补片／纹样／遮挡是否穿帮。

露缝修素材、锚点或层序；动作僵硬修轨迹和时序；脱手修接触；持续扭曲则调整表达方法。修后重跑同一段，保留前后预览，不重生成无关部件。不能偷偷删动作、缩小范围或改镜头掩盖失败。无法完整播放就记录未播放，并按顺序检查全部帧，不把联系表当成已看片。

范围、身份或镜头意图没有变化的候选返修由执行者继续做，不新增逐层确认。代表片段成立后扩展其他动作；新片段仍用相同方式验证，不能据一个动作通过宣称全部能力通过。

## 交付与正式接入

任务输出只保留实际使用的独立素材、原生 manifest、动作数据／脚本、连续预览与需要的可编辑工程。生成参数和问题可记入既有任务记录或 manifest；不要求为每轮新建文档。原生数据中的 ID、路径、坐标、动作范围和版本须足以重放。

中间候选可直接在所有者仓库装配预览；正式资产锁定与 Gate 仍沿用[总控](工作流-全流程总控.md)，不增加新的 Gate。已有批准不自动失效，只有实际受影响的素材／动作需重测；正式交接保留[资产身份与证据](技能协作与交付契约.md)，不把本流程变成上传或审批操作。

最终交付检查：素材独立可用、目标动作连续成立、工程可重放、未满足项明确。透明度、文件存在、帧差、骨架和限位测试只能提供技术证据，不能替代观看判断。
