# 分阶段建模流程修改与验证（2026-11-13）

## 修改范围

沿用 blender-python-modeling，没有新增 Skill。主入口、建模方法、任务分析、完成条件和阶段执行文档统一采用：用途与结构分析 → 按模块选择方法 → 低成本基础形体 → 实际验收 → 细化 → 按用途完成后续验收。

方法覆盖 primitives、box、surface、curve、sculpt 和 reuse。Cube 可用于低模盒式建模；不把增加细分当作完善结构的替代。已有模型允许保存快照后直接验收相关范围，连续网格允许绑定多个语义模块，不要求为流程拆开人物皮肤。

通用脚本模板移除默认 Cube，未实现的 builder 明确失败。参考锚点 Cube 移至独立教学示例，复用正式模板。新增计划、待检查评审模板和 blockout_gate，沿用现有 stage_guard 与模块台账，不升级台账 schema。

细化前需要当前作用域的验收记录，包含实际检查、证据哈希与检查状态签名。粗模、计划、已声明依赖或证据改变后旧回执失效；不能重新登记旧评审文件来跳过检查。默认细化派生副本并检查粗模未改变。仅检测违规修改，不自动回滚；恢复需使用项目快照。模块清理拒绝删除其他模块仍绑定的共享对象。

知识目录新增两条，105 → 107，保持 experimental；新增三个开发评测任务和四个检索回归查询。评审可由实际检查的 Agent 或人工填写，没有增加逐阶段用户批准要求。

## 证据边界

这些测试验证协议、状态失效与 Blender 操作行为，不证明复杂角色、汽车或完整资产的艺术品质，也没有新的真实 Agent 成对收益结论。合成测试中的评审明确标记为 synthetic-integration-only；生成一张 PNG 不等于视觉验收通过。

默认状态适配器检查求值 mesh/curve 与帧，实际项目仍需声明外部缓存、姿态和其他影响检查的上下文。特殊表示或成熟拟合器可接入等价冻结状态检查；不得把有限哈希当作自动发现全部依赖或自动视觉评分。
