# 角色绑定、蒙皮与导出

适用：可变形角色新绑定、权重修复或骨骼动画导出；静态雕塑不自动进入此流程。先读 [角色交付](../../character-delivery.md)。

1. 检查实际网格、现有骨架/形态键/动作、尺度、静止姿态、关节体积与拓扑。已有兼容绑定只修必要部分，不能因工具预设不同而重绑。
2. 如静止网格无法支撑运动，保留源资产，准备派生变形网格；如骨架轴/层级不合理，先改骨架并评估已有动画依赖，最后再做权重。
3. 新骨架根据关节标记放置骨骼与弯曲方向，区分变形/控制骨，确定根运动和目标引擎。自动权重仅是初值；检查未赋权、非单位和、跨肢体影响、超平台影响数与不存在的骨组。
4. 数值异常先局部清理；数值正确但视觉异常时检查骨轴、拓扑、修改器顺序和蒙皮方法，不重复归一化来碰运气。控制组/遮罩组不参与 deform 归一化。
5. 按请求验证基础 FK、完整活动范围或行走接触。只做小幅 FK 不得标为 locomotion validated；行走需要完整周期、实际足底、支撑/摆动和循环接缝。
6. 仅在交付边界建立导出副本，按目标烘焙约束/驱动，保留源骨架和动作。导出后在隔离场景或目标引擎重新载入，比较静止姿态、关键动作、形态键和材质。

失败时区分源场景问题与导出变换/采样问题；源正常而导出异常优先检查导出副本、轴、采样和动作筛选。按 [角色导出验收](../../acceptance/character-export.md) 检查；未知平台能力保持未验证。

## 可执行的持久绑定路径

[character_rig.py](../../../scripts/character_rig.py) 的 `build_rig(scene, name, bones, bindings)` 使用明确的世界坐标关节和逐顶点 deform 权重创建持久骨架/Armature modifier，不生成“通用人体猜测”。bones 按父先于子排列，记录 head/tail、parent、roll；关节位置必须从已审阅的静止姿态确定。bindings 为实际 mesh object 到每个顶点权重字典的映射，长度和骨名必须匹配源网格；未知骨、零权重、权重和错误和超限在创建前拒绝。已有绑定走局部修复，不重复套用新骨架。

处理分支：

- 关节没有足够边环或静止网格相互粘连：先准备变形拓扑，再放骨/赋权，不靠更多骨头补救。
- 分离硬配件：依据附件关系刚性绑定到相应骨；不能把整件衣服、皮肤和头发全部交给全局最近骨来猜。
- 柔性关节：按明确肢体区域生成初始权重，再对关节带过渡检查；禁止跨左右肢体串权。
- 权重数值通过但抬臂/屈肘/屈膝塌陷：回查骨轴、拓扑、体积和必要修正，不重复归一化。
- 实时预算超限：在保留原模型的前提下制作低成本派生网格，重新检查形体和权重；不在已绑定源上直接无条件减面。

`rig_inventory` 调用现有权重检查；它只验证持久结构和数值。实际肩/肘/膝应根据目标活动范围建立 rest、代表中间姿势和极值检查，保存灰模/材质视图，并连续播放。构建函数默认线性蒙皮便于基础 glTF 对照；preserve_volume/DQ 与目标线性蒙皮差异要单独验证，不默认为等价。

基础常量 PBR、已准备好的一套线性骨架/动作，可用 [隔离交付](../../production-workspace.md) 的 rigged 模式，显式列出骨架、父级和全部交付网格。多动作/约束/形态键/复杂材质按完整角色交付准备和目标审阅。本轮合成双骨夹具只认证操作机制，不能认证完整人体解剖或行走。

现有 `fit_character.py` 为静态参考拟合，不自动创建生产骨架；`--rig-test` 的 probe_only 成功不能升级为 rigged。拟合配置可声明 `validation.max_triangles`，按实际求值三角面阻断超预算；没有声明时保持预算未知，而非自动套用 8 万面。
