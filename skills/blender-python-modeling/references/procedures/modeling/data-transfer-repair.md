# 拓扑改变后的权重、UV 与属性迁移

适用：派生低模、局部重拓扑、衣物/附件需要接收既有数据。输入是明确的源/目标网格、坐标空间、待转移的组/UV/颜色/法线及排除区域。依据：[Data Transfer 来源](../../sources/production-sources.md)。

## 判断映射

- 顶点/面索引对应已被稳定 ID 或构建历史证明，数量和顺序一致：可使用 Topology 映射。只有数量相等不足以证明对应，重排顶点后必须重新确认。
- 拓扑不同但表面接近：选择最近顶点、最近面插值或投射；检查世界空间重叠、法线方向、最大距离、遮罩和层选择。
- 邻近薄片、手指、上下唇、衣物两层：按部位分源/分目标或用组限制，先排除跨层污染。不能靠无限加大搜索距离补齐未匹配区域。
- 形态键：普通属性转移不保证形态键的顶点对应。拓扑改变需独立的重建/投射策略和表情验证，不能声称自动保留。

## 执行与失败处理

1. 保存源、目标副本和数据清单；锁定静止姿态/变换。只启用任务所需数据类型与命名层，明确覆盖还是混合。
2. 在代表区域试迁移，报告未匹配、超距离、跨区域影响和缺失层。 [production_checks.py](../../../scripts/production_checks.py) 提供只读事实与 correspondence_status 辅助；unknown 需要继续检查。
3. 权重转移后仅对 deform 组检查和/影响数，再测试关节；UV 用棋盘纹理并检查岛边界；法线在目标材质/三角化后查看。数值正常仍可能发生跨指污染。
4. 若错误集中于一层/一组，回到映射、遮罩与区域分离；不要对所有组反复归一化或覆盖源。

按 [网格恢复与数据迁移验收](../../acceptance/mesh-recovery.md) 交付。保留数据层前后清单、局部对照及使用的映射配置，不将“生成了某个同名组”视为成功。
